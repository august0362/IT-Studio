## 1. Approach

| Aspect | Choice |
|---|---|
| Lifecycle | Incremental milestones (one capability each), contracts-first, each closed by a QA gate (TESTING §7). |
| Work unit | One task = one concern, ≤ 400 changed lines, one Codex run (+ ≤ 6 fix attempts, HANDOFF §3 rule 5). |
| Sizes | **S** ≤ 150 lines · **M** ≤ 300 · **L** ≤ 400 (split if larger, suffix `a/b`). |
| Parallelism | ≤ 3 Codex runs at once (4 if one is test-only), only on disjoint *Scope* paths; `container.ts`, `schemas.ts`, `i18n/*.json`, `AppShell/MainNav` conflicts are expected and resolved by QA. |
| Architect pre-work per milestone (`Mx-00`) | (1) apply the milestone's additive contract changes from the SRS §6 to `src/types/schemas.ts` (+ keep typecheck green — validators are added by the first task that registers the RPC), (2) pre-install dependencies in one commit, (3) re-read and adjust task files, (4) answer the milestone's open questions with the owner. |
| Migrations | Generated by the Architect after the task that changes `infra/sqlite/schema.ts` (never hand-written). |
| QA | Lean routine (HANDOFF §2.3); milestone gate writes `docs/qa/Mx-test-cases.md` from the outline in `docs/tasks/Mx-QA.md`. |

### 1.1 Definition of Ready (task)
Task file exists and is committed · requirement IDs cited · Scope paths listed · contracts it needs exist in `schemas.ts` (or the task is explicitly allowed to add them) · dependencies ticked · deps pre-installed.

### 1.2 Definition of Done (task)
Acceptance criteria met · `typecheck`, `lint`, `test` green · integration for the touched area green (QA) · coverage gate where stated · `## Result` + `## QA (Claude) — final` in the task file · ROADMAP ticked · CHANGELOG line.

### 1.3 Definition of Done (milestone)
All tasks ticked · `Mx-QA` report signed off (100 % P1, ≥ 95 % P2, no open S1/S2) · ROADMAP exit criteria demonstrated · HANDOFF updated.
