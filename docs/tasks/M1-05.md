# M1-05 — SQLite infra, Settings & Project services

Milestone: M1 · Depends on: M1-01, M1-02 · Role: Implementer (ROLES §1.3) · **Deps pre-installed** (`better-sqlite3`, `drizzle-orm`, `drizzle-kit`, `@types/better-sqlite3`)

## Goal
Persistent storage exists (SQLite, WAL, forward-only migrations) and the UI can read/update settings and manage projects over RPC.

## Read first
- `AGENTS.md`, `ARCHITECTURE.md` §1, §4, §12, `CONVENTIONS.md` §2.1, §3, §7 (SQL), `schemas.ts` §2, §12, §12a, `config/README.md`, `docs/design/THEMES.md` §5 (default theme ids)

## Requirements
1. `openDatabase(dataDir)` → `<dataDir>/itstudio.db`, pragmas `journal_mode=WAL`, `foreign_keys=ON`, `busy_timeout=5000`; runs drizzle migrations from the committed `migrations/` folder at startup (forward-only). In-memory DB (`:memory:`) for tests.
2. Tables: `projects (id text pk, name text not null, workspace_root text not null unique, created_at text not null, archived integer not null default 0)`, `settings (id integer pk check(id=1), json text not null, updated_at text not null)`.
3. Ports + repos: `IProjectRepository` (list, get, create, setArchived), `ISettingsRepository` (load, save). Drizzle query builder only (no `sql.raw`).
4. `domain/default-settings.ts`: `buildDefaultSettings(seeds: Seeds): AppSettings` — complete defaults: ladder/roles/embedding/extraction model from seeds; `autoFallback: true`; circuit `{failureThreshold: 3, cooldownMs: 120000}`; `userDecisionTimeoutMs: 120000`; `budget.hardStop: false`; pricing `{autoUpdate: true, updateIntervalHours: 24, maxAutoChangePercent: 50}`; fx `{autoUpdate: true, manualUsdToVnd: null}`; vscode `{autoLaunch: true, codeExecutable: null, showDiffBeforeValidate: true, revealChangedFiles: true}`; pipeline `validationCommands` from `config/commands.default.json`, `maxFixAttempts: 1`; rag chunking `{targetTokens: 500, overlapTokens: 80, respectHeadings: true}`, `defaultTopK: 6`, `minScore: 0.35`; image `{enabled: false, providerOrder: ['openai_dalle3','flux_together','flux_replicate']}`; ui `{themeId: catalog.defaultLight, mode: 'system', locale: 'en'}`; `activeProjectId: null`.
5. `SettingsService`: `get()` (load or create defaults; stored JSON validated with `appSettingsSchema` — if invalid, log warning, back up the bad row to `settings_backup_<ts>.json` in data dir, reset to defaults); `update(patch: SettingsPatch)` deep-merges one level per `SettingsPatch`, validates the full result, persists, returns it. Reject `pipeline.maxFixAttempts` ≠ 1 and unknown `ui.themeId` (check against `config/themes.json` ids) with VALIDATION.
6. `ProjectService`: `list`, `create(name, workspaceRoot)` — `workspaceRoot` must be absolute, exist, be a directory, not be a filesystem root, not already registered (CONFLICT); `setActive(projectId)` updates settings `activeProjectId`.
7. Register RPC: `settings.get`, `settings.update`, `project.list`, `project.create`, `project.setActive`.

## Tests
- Migrations apply on fresh in-memory DB; re-open is idempotent.
- Defaults validate against `appSettingsSchema` and use seed values.
- `settings.update` merge semantics, validation failures, corrupted-row recovery.
- Project create: relative path, non-existent, file-not-dir, duplicate → correct error codes.
- RPC round trip through `RpcServer` for each registered method.
