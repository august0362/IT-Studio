# M11-04 — Memory recall: scoring, context injection, `recall_memory` tool

Milestone: M11 · Depends on: M11-01 · Role: Implementer · Size M · **Deps pre-installed**
Requirements: FR-MEM-06, FR-MEM-07 · ARCH §16.3

## Goal
Each agent turn starts with the most relevant memories of that agent (plus pinned ones) injected as data, and the agent can search memory on demand.

## Scope
- `apps/sidecar/src/domain/memory-recall.ts` (+ test: pure scoring/selection), `services/memory-recall-service.ts` (+ test), `services/agent-tools/recall-memory-tool.ts` (+ test, replaces the stub), `services/agent-runner.ts` (inject block + record ids)

## Requirements
1. Score per ARCH §16.3 with injected clock; cosine floor 0.3; top `recallTopK` (0 disables); pinned (max 5) always included, ranked first; expired excluded; `projectIds` = [conversation project] + [null if `shareAcrossProjects`].
2. Query vector = embedding of the user's latest message (one embedding call, purpose `embedding`); skip recall when the agent's memory is disabled or the store is empty for the agent (no embedding call).
3. Injection: `<context name="memory">` with numbered items `[m1] (kind, importance) text` placed before RAG context; the system prompt notes memories may be outdated.
4. Update `lastRecalledAt` for injected items (batch update); store ids on the run (`recalledMemoryIds`).
5. `recall_memory` tool (`RecallMemoryArgs`, topK 1–20) returns items with ids, kind, text, score.

## Tests
Scoring table (importance 1/5, age 0/90/180 days, cosine 0.29/0.3, pinned > topK), selection ordering, no-embedding-when-empty, tool parse/limits; runner test verifying the block and ids.
