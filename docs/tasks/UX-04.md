# UX-04 — Workflow map becomes a "System map" tab inside Processes

Milestone: v1 owner acceptance feedback (2026-10-16) · **After OWNER-FB3 lands** · Role: Implementer · Size S · **Deps pre-installed** · **Broad scope inside `apps/desktop/src/**`: do not stop for edits needed to meet a requirement — list them in Result**

## Owner decision

The Workflow page (live map of IT Studio's modules) overlaps with Processes. Merge it into Processes as a tab and remove it from the sidebar.

## Requirements

1. Processes page gets two tabs: **Processes** (current list, default) and **System map** (vi: "Sơ đồ hệ thống") rendering the existing Workflow graph component (`features/workflow`) unchanged in behaviour (fit view, activity dots, module panel).
2. Sidebar: remove the Workflow entry. `#workflow` deep links and every in-app link to the workflow route open Processes → System map. Workflow module-panel deep links (open chat, open run, …) keep working.
3. In System map, the module panel gets a button **"Show processes"** that switches to the Processes tab filtered to the matching kinds (Chat module → `chat`, Pipeline → `code_pipeline`, Knowledge/RAG → `knowledge_ingest`, Images → `image`, Pricing → `price_update`, VS Code → `vscode_launch`, Web chat → `web_chat`; modules without a kind hide the button).
4. The selected tab is remembered in `localStorage` (try/catch).

## Tests (lean)

Tabs switch and persist; `#workflow` lands on System map; "Show processes" filters by kind; sidebar has no Workflow entry; existing workflow component tests still pass (update navigation helpers only).

- [ ] `npx prettier --write <changed files>`, `npm run typecheck`, `npm run lint`, `npm test` pass. QA runs E2E `mw/workflow.spec.ts` (navigation changed).
