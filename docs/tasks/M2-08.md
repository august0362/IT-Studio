## Requirements
1. `UserFallbackDecider implements IFallbackDecider`: on request, build `FallbackDecisionRequest` (candidates in ladder order with `estimatedCostMicroUsd` via `domain/cost.ts#estimateRequestCost` and current price table; if no price → 0), `expiresAt = now + userDecisionTimeoutMs`; publish `router.fallbackRequired`; await `router.resolveFallback` for that `requestId` or expiry → `user_timeout`. Late/unknown decisions → `{accepted:false}`.
2. RPC `router.resolveFallback` validated: `use_model` key must be among candidates.
3. `RouterConfigService` (reads/writes `settings.router` through `SettingsService`): `router.getConfig`, `router.updateConfig` with validation — unique priorities 1..n contiguous after renumbering, every key exists in `ModelRegistry`, `lockedModelKey` null or existing, `maxRetries` 0..5, `timeoutMs` 5_000..300_000, `userDecisionTimeoutMs` 10_000..600_000.
4. Router reads config live (changes apply to the next request).

## Tests
- Decision flows: use_model, retry_same, abort, timeout (fake clock), invalid model rejected, duplicate decision ignored.
- Config validation failures; renumbering; persistence round-trip.
