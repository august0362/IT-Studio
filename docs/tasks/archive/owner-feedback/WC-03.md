## Owner request

"In the web-chat area I want to drag the panes freely, maximize and minimize them, smoothly, and let them overlap other panes."

## Background

Each pane is a **native child webview** (Tauri, `webchat.rs`) placed over the React page; React only computes bounds and calls `webchat_sync`. Native webviews always paint above the main webview, so HTML chrome drawn under them is hidden, and moving them every pointer event is janky.

## Requirements

1. **Layout mode switch** in the Web chat toolbar: **Tiled** (today's 1â€“4 split panes, unchanged) and **Free** (floating windows). The mode is persisted.
2. **Free mode window frame (React):**
   - Title bar: site icon/initial, name, buttons *Minimize*, *Maximize/Restore*, *Open in browser*, *Close*. All are labelled buttons.
   - Drag by the title bar; resize from the 4 edges and 4 corners (min 360Ă—280, clamped inside the web-chat area).
   - Double-click the title bar maximizes or restores. Optional edge snap (half/full) when released near an edge.
3. **Z-order and overlap:**
   - Clicking a window or its title bar brings it to the front. Windows may overlap.
   - The native webview of each window is placed inside its frame below the title bar.
   - Native z-order must follow the React z-order. Implement a `webchat_raise(paneId)` command in `webchat.rs` that brings that child webview to the top. Research the Tauri 2 / WebView2 API in the pinned versions (e.g. re-adding or reordering the child webview, or `SetWindowPos` on the controller's parent HWND).
   - Window titles must never be hidden under another window's webview: the frontmost window's title bar is drawn in a thin native-free strip, or other webviews are clipped/hidden where they intersect. Choose the approach that works and document it.
   - If true native z-order is impossible, write `## Blocked` with evidence instead of faking it.
4. **Smoothness:**
   - While dragging or resizing, hide the moving window's native webview and show a lightweight placeholder (site name, icon, subtle glass/blur style) that follows the pointer at 60 fps via `requestAnimationFrame`.
   - On release, sync the bounds once and show the webview again. Other windows stay live.
   - Maximize/restore/minimize animate the frame (150â€“250 ms), then sync.
   - Respect `prefers-reduced-motion`.
5. **Minimize:** minimized windows go to a dock bar at the bottom of the web-chat area (chips with icon + name); clicking a chip restores the window and brings it to the front. Minimized panes hide their native webview but keep their session.
6. **Persistence:** per window, position, size, maximized/minimized state and z-order are saved in the existing web-chat layout settings (additive fields, validated and normalised) and restored on reopen. Tiled-mode layout is untouched.
7. **Limits:** up to 6 windows in Free mode (4 in Tiled as today). Opening a site that is already open focuses its window.
8. **Keyboard/a11y:** focusable title bar; `Alt+Arrow` moves a focused window by 24 px and `Alt+Shift+Arrow` resizes it; Esc during a drag cancels it.
