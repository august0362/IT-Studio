# UX-03 — One Settings page instead of a long sidebar

Milestone: v1 owner acceptance feedback (CONTEXT D39) · **After OWNER-FB2-B lands** · Role: Implementer · Size S–M · **Deps pre-installed** · **Broad scope inside `apps/desktop/src/**`: do not stop for edits needed to meet a requirement — list them in Result**

## Owner request

"Put everything that can be configured into one Settings module — the sidebar has too many things."

## Requirements

1. **Sidebar** (`shell/MainNav.tsx`): only the main features, in this order — Projects, Chat, Web chat, Code, Knowledge, Gallery, Cost, Workflow (and Processes when PROC-02 lands) — then, pinned at the bottom, one **Settings** item (gear icon + label). No settings sub-items in the sidebar.
2. **Settings page** (`features/settings/SettingsPage.tsx`, route `settings`): left sub-navigation (on narrow windows, a select at the top) with sections, in this order: *API keys*, *Router*, *Pipeline*, *Budget*, *Pricing*, *Currency (FX)*, *Images*, *Web chat*, *VS Code*, *Appearance & language* (theme page), *Labs* (holds the **Pipeline Studio** launcher button that is in the sidebar today; keep `PipelineStudioNavButton` and its flag behaviour). Each section renders the existing page component unchanged.
3. **Search box** at the top of the sub-navigation filters sections by title and by a few keywords per section (e.g. "key", "fallback", "budget", "theme", "dark", "language", "VND").
4. **Deep links keep working:** `#settings-api-keys`, `#settings-router`, … open the Settings page with that section selected; every in-app link that navigates to a settings route (e.g. "Open Settings → Pipeline", pricing hints) still lands on the right section. The last opened section is remembered in `localStorage` (try/catch).
5. Keyboard: sub-nav is a list of links with `aria-current`; Settings heading has the section title; focus moves to the section heading on change.

## Tests (lean)

Sidebar contains no settings sub-items and one Settings entry; each `#settings-*` hash selects the right section; search filters; Pipeline Studio button lives in *Labs* and respects `PIPELINE_STUDIO_ENABLED`; existing settings page tests still pass (update only their navigation helpers).
