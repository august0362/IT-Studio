# M12-03 — Outbox: state machine, service, send cap, `outbox.*` RPC, `draft_reply` tool

Milestone: M12 · Depends on: M12-01 · Role: Implementer · Size L · **Deps pre-installed**
Requirements: FR-OB-01…07, NFR-V2-05 · D22 · SRS v2 §7.2

## Goal
Every outbound message is a draft until the owner approves it; approval is the only path to `adapter.send`; sends are capped and never duplicated.

## Scope
- `apps/sidecar/src/domain/outbox-machine.ts` (+ test), `domain/send-cap.ts` (+ test), `services/outbox-service.ts` (+ test), `ports/outbox-repository.ts`, `infra/sqlite/outbox-repository.ts` (+ test), `services/agent-tools/draft-reply-tool.ts` (+ test, replaces stub), validators, `container.ts`, `domain/remediation.ts` entries, `src/types/schemas.ts` RPC `outbox.list|update|approve|reject|retry|counts` + notification `outbox.changed`
- integration `apps/sidecar/test/integration/outbox.test.ts`

## Requirements
1. Transition table exactly SRS §7.2 (pure; illegal → `CONFLICT`).
2. `draft_reply` (`DraftReplyArgs`): `inReplyTo` must be a message of an account whose channel is in the agent's `channels`; creates `pending_approval` with `to` = original sender, subject `Re: …` (Gmail) and `sendBefore` from the adapter rules (Facebook in M14 — field set via an adapter hook `computeSendBefore(message)`); links the item to the run (`outboxItemIds`).
3. `approve(itemId)`: re-read item; expired check (`sendBefore <= now` → `expired` + `MESSAGING_WINDOW_EXPIRED`); cap check (`send-cap`: count `outbox_sends` in the last 60 min ≥ 20 → `OUTBOX_SEND_CAP` with `details.nextAllowedAt`); in-memory `sending` guard; **persist `failed` with error "Send started; outcome unknown — check the Sent folder" before calling the adapter**, then on success set `sent` + `externalMessageId` + insert `outbox_sends`; on adapter error set `failed` with that error. (A crash mid-send leaves `failed/unknown`, never resends automatically — NFR-V2-05.)
4. `update`: only `pending_approval`; validation per channel (Gmail RFC 5322 addresses via a small pure validator; Facebook body ≤ 2 000, `to` immutable).
5. `counts`: pending approvals + untriaged messages (for nav badges).
6. No bulk approve method exists (FR-OB-05).

## Tests
Machine: every cell of the table. Cap at 19/20/21 sends and window boundary (60 min ± 1 s). Service: duplicate approve while sending → `CONFLICT`; crash simulation (adapter promise never resolves + restart) → item `failed`, not resent. Integration `TC-M12-010` draft → approve → fake adapter received exactly one send; `TC-M12-011` reject; `TC-M12-012` cap.
