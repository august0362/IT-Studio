# M5-01 — Document parsers (md, txt, code, pdf, docx, html)

Milestone: M5 · Depends on: M5-02 · Role: Implementer (ROLES §1.3) · **Deps pre-installed** (`pdfjs-dist`, `mammoth`, `html-to-text`)

## Goal
Turn a user-selected file into normalized plain text (+ format) ready for the chunker, with strict size/type guards (ARCH §7.1).

## Read first
- `AGENTS.md`, `ARCHITECTURE.md` §7.1, `schemas.ts` §7 (`DocumentFormat`), `apps/sidecar/src/domain/chunker.ts`, `apps/sidecar/src/ports/file-system.ts`

## Scope
- `apps/sidecar/src/services/rag/parsers/**` (+ tests), test fixtures under `apps/sidecar/src/services/rag/parsers/fixtures/` (small, generated in tests where possible; commit tiny real `.pdf`/`.docx` samples ≤ 50 KB each)

## Requirements
1. `detectFormat(path)`: by extension — md/markdown → markdown; txt/log → text; pdf; docx; html/htm → html; code extensions (ts, tsx, js, jsx, mjs, cjs, py, rs, go, java, cs, cpp, c, h, json, yaml, yml, toml, sql, sh, ps1, css, scss) → code; anything else → unsupported (`VALIDATION`).
2. Guards: file ≤ 20 MB (else `VALIDATION` with remediation), binary detection for text/code (NUL bytes in first 8 KB → unsupported), UTF-8 decoding with BOM stripping; invalid UTF-8 → replacement chars allowed, recorded in `warnings`.
3. Parsers return `{ text, format, title, warnings }`: markdown/text/code raw (normalized `\n`); **pdf** via `pdfjs-dist` legacy build (text per page joined with `\n\n`, no worker thread in Node; password-protected/corrupt → `VALIDATION` with remediation); **docx** via `mammoth.convertToMarkdown` (keeps headings for the chunker); **html** via `html-to-text` (headings preserved as markdown-like `#` lines, scripts/styles dropped). Title = first heading or file name.
4. All file reads go through `IFileSystem` (testable with the memory FS); no network.

## Tests
- Each format happy path; size limit boundary (20 MB − 1 / + 1 via memory FS); binary rejection; BOM; corrupt pdf/docx; html with `<script>` removed; unsupported extension.
