# UX-01 — API Keys: "Verify" saves a typed (unsaved) key first

Milestone: v1 owner feedback · Depends on: — · Role: Implementer (ROLES §1.3) · Size S · **Deps pre-installed**

## Problem (reported by the owner, 2026-10-04)
In Settings → API Keys the owner typed a Google key and clicked **Xác minh** (Verify) without clicking **Lưu** (Save). Verify checks only the *stored* key, so the sidecar returned `SECRET_MISSING` ("No API key is configured for google") and the row was marked "Không hợp lệ" (Invalid) while the typed key was still in the field. Users reasonably expect Verify to check what they just typed.

## Scope
- `apps/desktop/src/features/settings/api-keys/ApiKeysPage.tsx` (+ `ApiKeysPage.test.tsx`)
- `apps/desktop/src/i18n/{en,vi}.json` (new/changed keys for this page only)

## Requirements
1. **Verify with a typed key:** if the provider's input is non-empty, Verify first performs the same save as *Save* (`secrets.set`, clears the field before the RPC as today), and only if the save succeeds calls `secrets.verify`. One busy state covers both calls. If the save fails, show the save error and do not verify.
2. **Verify with an empty field and no stored key:** do not call the RPC; show a friendly inline message (en: "Type the API key, then click Save or Verify." / vi: "Nhập API key rồi bấm Lưu hoặc Xác minh.") and do **not** mark the row Invalid.
3. "Invalid" status is shown only when the provider actually rejected the key (verification failure other than `SECRET_MISSING`). A `SECRET_MISSING` result shows status "Chưa cấu hình" / "Not configured".
4. Pressing Enter in the field keeps meaning Save (existing form behaviour).
5. The secret never stays in React state after a successful save (existing guarantee kept); no key text in error messages.

## Tests
Component tests: typed key + Verify → `secrets.set` then `secrets.verify` in order, field cleared; save failure → no verify, error shown; empty field + nothing stored → no RPC, friendly message, not Invalid; provider rejection → Invalid; `SECRET_MISSING` → Not configured; existing tests stay green.
