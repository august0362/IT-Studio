## Read first
`AGENTS.md`, **ARCHITECTURE §14.2**, `apps/desktop/src-tauri/{tauri.conf.json,Cargo.toml,src/lib.rs,src/sidecar/spawn.rs,src/sidecar/*.rs}`, `scripts/build/build-sidecar.mjs` (output layout: `dist-sidecar/itstudio-sidecar-x86_64-pc-windows-msvc.exe` + `dist-sidecar/resources/**` with a sha256 manifest), Tauri v2 docs for `bundle.externalBin`, `bundle.resources`, NSIS / WiX targets and `webviewInstallMode`.

## Scope
- `apps/desktop/src-tauri/tauri.conf.json` (bundle section), `apps/desktop/src-tauri/src/sidecar/spawn.rs` (the `#[cfg(not(debug_assertions))]` path) + Rust tests, `apps/desktop/src-tauri/capabilities/**` only if the shell plugin needs a permission, `scripts/build/build-app.mjs` (new), root `package.json` scripts (`build:app`), `.gitignore` (installer outputs).

## Requirements
1. `bundle.active = true`, targets **NSIS** and **MSI**; per-user install; `webviewInstallMode` = embedded bootstrapper; product name "IT Studio", identifier unchanged (`com.itstudio.app`), version from `tauri.conf.json`.
2. `bundle.externalBin` = the SEA sidecar (Tauri's `-x86_64-pc-windows-msvc` naming); `bundle.resources` = `dist-sidecar/resources/**` copied next to the sidecar so `native-modules.ts` finds `<exe dir>/resources/…` (verify the installed layout matches what the sidecar expects; adjust the resource mapping, not the sidecar).
3. Release spawn path (`cfg(not(debug_assertions))`): start the bundled sidecar exe from the app's install / resource dir, same env (`ITSTUDIO_DATA_DIR`, log level), same `CREATE_NO_WINDOW` flag, same supervision (restart backoff, fatal after 5). Debug path unchanged.
4. `npm run build:app` = `build:sidecar` → copy outputs into the Tauri source layout → `tauri build` (release) → prints installer paths and sizes.
5. Rust unit tests for path resolution (installed layout, missing sidecar → clear `SpawnError`). Do not code-sign here (M9-04).

## Acceptance criteria
- [ ] `npm run typecheck && npm run lint && npm test` and `cargo test` (in `apps/desktop/src-tauri`) pass; `npm run build:app` produces an NSIS `.exe` and an `.msi` — **QA builds outside the sandbox**, installs per-user to a temp location, launches the installed app and checks it reaches Ready with the bundled sidecar. Do not run E2E.
