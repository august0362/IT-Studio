# M1-01 — zod validators mirroring the contracts

Milestone: M1 · Depends on: M0-06 · Role: Implementer (ROLES §1.3) · **Deps pre-installed** (`zod@^4` in `apps/sidecar`)

## Goal
Every payload that enters the sidecar (RPC params, extension messages, LLM role outputs, config seed files) can be parsed from `unknown` into the exact `schemas.ts` type, and type tests prove validators and contracts cannot drift.

## Read first
- `AGENTS.md`, `CONVENTIONS.md` §2, §2.1, §6, `ARCHITECTURE.md` §1 (principle 2), §3.3, `src/types/schemas.ts` (all), `config/README.md`

## Scope — files you may create/modify
- `apps/sidecar/src/validation/**` (new)
- `apps/sidecar/src/config/load-seeds.ts` + test (new)

## Requirements
1. `validation/brand.ts`: one zod schema per branded type. Ids: `z.uuid()` → transform to brand. `IsoDateTime`: `z.iso.datetime()` (UTC, `Z` suffix). `MicroUsd`/`Vnd`: `z.number().int().nonnegative()` (`MicroUsd` may be negative only in `ProjectPnL.margin` — model that with a separate `signedMicroUsd`). `WorkspaceRelativePath`: non-empty, no leading `/` or `\`, no drive letter, no `..` segment, no NUL, normalised to `/` separators. `Sha256`: `/^[a-f0-9]{64}$/`. `ModelKey`: `/^(anthropic|openai|google|xai|groq|together|replicate)\/[A-Za-z0-9._:-]+$/`. This file is the **only** place `as` casts are allowed (CONVENTIONS §2.1).
2. One module per `schemas.ts` section (`errors.ts`, `projects.ts`, `models.ts`, `chat.ts`, `router.ts`, `cost.ts`, `rag.ts`, `pipeline.ts`, `worker.ts`, `ipc.ts`, `vscode.ts`, `settings.ts`, `image.ts`) exporting `<camelName>Schema` for every exported interface/union used at a boundary. Use `.readonly()` for readonly arrays/objects; discriminated unions via `z.discriminatedUnion`.
3. `ipc.ts`: `rpcParamsSchemas: { [M in RpcMethod]: z.ZodType<RpcMethodMap[M]['params']> }` — exhaustive (a missing method must be a compile error), and `rpcRequestEnvelopeSchema` (jsonrpc '2.0', integer id ≥ 0, string method).
4. `vscode.ts`: `extToSidecarSchema` (all `ExtToSidecar` members; `ExtHello.protocolVersion` literal 1).
5. `pipeline.ts`: `taskSpecSchema`, `coderOutputSchema`, `reviewVerdictSchema` with limits: max 50 `allowedPaths`, max 200 operations, file content ≤ 1 MiB each, finding message ≤ 2000 chars. Export `toJsonSchema(schema)` helper using zod v4 `z.toJSONSchema` (used by role prompts in M6-04).
6. `config/load-seeds.ts`: `loadSeeds(configDir: string): Result<Seeds>` reading `config/*.json` (see `config/README.md` for shapes; define `FxConfig` and `Seeds` types locally in this file — they are sidecar-internal). Cross-checks: every ladder/role/embedding/pricing-extraction `modelKey` exists in `models`; ladder priorities unique; every enabled model has a price entry (warn-only list returned in `Seeds.warnings`).
7. Helper `parse<T>(schema, input: unknown): Result<T>` mapping zod errors to `AppError{code:'VALIDATION', message, details:{issues}}` (issue paths + messages only, never input values).

## Type-drift tests (`validation/*.test.ts`)
For each schema: `expectTypeOf<z.output<typeof s>>().toExtend<Contract>()` **and** `expectTypeOf<Contract>().toExtend<z.output<typeof s>>()`. If `exactOptionalPropertyTypes` makes the second direction impossible for a schema, keep the first, add a comment explaining why, and list the schema in `## Result`.

## Runtime tests
- Each branded schema: valid + ≥ 3 invalid cases (path traversal variants for `WorkspaceRelativePath`).
- `rpcParamsSchemas`: one valid + one invalid sample for 10 representative methods.
- `loadSeeds` on the real `config/` directory → ok, zero errors; on a temp dir with a bad ladder key → VALIDATION.
- `reviewVerdictSchema` rejects unknown severity; `coderOutputSchema` rejects `../x` path.

## Acceptance criteria
- [ ] `npm run typecheck && npm run lint && npm test` exit 0; `apps/sidecar/src/validation/**` coverage ≥ 90 % lines
- [ ] Removing any method from `rpcParamsSchemas` causes a type error (state how you verified in Result)
- [ ] `loadSeeds(config)` succeeds on the committed seed files (this also closes ROADMAP M0-07)
- [ ] No `as` casts outside `brand.ts`
