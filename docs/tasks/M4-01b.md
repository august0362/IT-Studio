# M4-01b — Theme system (18 palette-derived themes, light/dark/system) + Settings → Theme picker

Milestone: M4 · Depends on: M4-02 · Role: Implementer (ROLES §1.3) · **Deps pre-installed**

## Goal
Implement `docs/design/THEMES.md` §5–§7: semantic color tokens as CSS variables, no-flash startup, OS-mode following, and the Theme picker — replacing the temporary `neutral-classes.ts` colors.

## Read first
- `AGENTS.md`, `docs/design/THEMES.md` (all), `config/themes.json`, `schemas.ts` §12a (`ThemeCatalog`, `ThemeTokens`, `ThemeMode`, `UiSettings`), `apps/desktop/src/components/ui/neutral-classes.ts`, existing components

## Scope
- `apps/desktop/src/theme/**` (new), `apps/desktop/index.html` (inline pre-mount script), `apps/desktop/src/index.css` (Tailwind `@theme` mapping), `apps/desktop/src/features/settings/theme/**` (new), `apps/desktop/src/App.tsx` (add Theme to Settings nav), existing components/pages to swap neutral classes for token classes, `apps/desktop/src/components/ui/neutral-classes.ts` (delete when unused), `eslint.config.js` (only to add the raw-color rule from THEMES §5.2), tests

## Requirements
1. `theme/catalog.ts`: static import of `config/themes.json`, validated with zod at module load (UI exception documented in THEMES §5.6); `resolveTheme(themeId, mode, prefersDark)` with fallback to `defaultLight/defaultDark`.
2. `theme/apply-theme.ts`: writes every token as `--color-<kebab>` (incl. `--color-chart-1..6`) on `document.documentElement`, sets `data-theme`, `data-mode`; 150 ms color transition disabled under `prefers-reduced-motion`.
3. No-flash: inline script in `index.html` reads `localStorage['itstudio.theme']` (`{themeId, mode}`) and applies tokens before React mounts (embed the minimal token map generation at build via Vite `define` or a tiny generated JSON — keep it < 15 KB); after `settings.get` resolves, sidecar settings win and the cache is updated (try/catch around storage).
4. `mode: system` follows `matchMedia('(prefers-color-scheme: dark)')` changes live.
5. Tailwind v4 `@theme` mapping so classes like `bg-bg bg-surface text-text text-text-muted border-border bg-primary text-primary-fg` work; replace all usages of `neutral-classes.ts` and any Tailwind default palette colors; ESLint rule forbidding Tailwind palette color classes (`/(bg|text|border|ring|from|to|via)-(slate|gray|zinc|neutral|stone|red|orange|amber|yellow|lime|green|emerald|teal|cyan|sky|blue|indigo|violet|purple|fuchsia|pink|rose)-\d{2,3}/`) in string literals under `apps/desktop/src/**`, plus a test that greps for `#[0-9a-fA-F]{3,6}` in `.tsx` files.
6. Settings → Theme page per THEMES §6: mode segmented control (System/Light/Dark), filter chips, responsive card grid (palette strip + mini preview + name + mood + ⓘ popover with psychology/recommendedFor), hover = preview panel only, click = apply + `settings.update({ ui: { themeId } })`, radiogroup keyboard navigation, "Reset default".
7. Status/money semantics: `<Money>` negative uses `--color-danger`; `<ErrorPanel>` uses danger tokens.

## Tests

- resolveTheme fallbacks; apply-theme sets variables/attributes; system mode listener; picker keyboard navigation, hover preview does not persist, click persists via RPC (fake transport); no raw hex in tsx; ESLint rule fixture rejects `bg-blue-500`.
- Add L4 E2E `e2e/specs/m4/theme.spec.ts`: TC-M4-001 switch to `midnight-focus` dark → `data-theme`/`data-mode` set, persists after app restart (QA runs).
