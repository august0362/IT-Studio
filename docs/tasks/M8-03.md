## Requirements
1. Tool `generate_image` declared to chat models only when `settings.image.enabled` (default stays `false` until the user enables it in Settings — add the toggle in M8-05).
2. Dispatch: validate `GenerateImageArgs` → BudgetGuard check with cost `perImageMicroUsd × count` (from the price table; unknown price → warning, cost 0) → provider ladder `settings.image.providerOrder` with the same fallback rules as the LLM router (classified failures) → store bytes under `<dataDir>/images/<projectId>/<assetId>.<ext>` → `ImageAsset` row → ledger row `purpose = image` → tool result `{ assetIds }` → assistant message gets `image` content parts.
3. Hard Stop blocks before any provider call; partial success (some images) keeps the stored ones and reports the failure.
4. `images.list` / `images.delete` (delete removes the file and the row; ledger stays — append-only).
5. `ITSTUDIO_E2E=1`: a fake provider returns a tiny deterministic PNG; no network.

## Tests

## Architect decision (resolves Blocked)

Add router unit tests for tool-call passthrough. Chat-service then executes `generate_image` and sends the `tool_result` back to the model in a follow-up turn (one tool round per user message, max 1 `generate_image` call per turn).
