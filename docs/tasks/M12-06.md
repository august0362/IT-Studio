## Scope
- `apps/sidecar/src/services/vscode-bridge.ts` (+ test): accept `protocolVersion` 1 and 2; v2-only messages; `apps/sidecar/src/services/vscode-chat-service.ts` (+ test); `validation/vscode.ts` (new variants); `container.ts`

## Requirements
1. Handshake: v1 clients behave exactly as today; v2 clients additionally receive chat messages. Unknown version → close with reason (existing behaviour).
2. `chat_list_agents` → enabled agents with `vscode` in `channels`.
3. `chat_send`: project = the project whose `workspaceRoot` matches the connected workspace (else `chat_error` VALIDATION "Open this folder as an IT Studio project first"); conversation = given id or a new one titled `VS Code: <first 40 chars>` bound to the agent; attachments wrapped as `<context name="vscode_selection|vscode_file" path="…">` (max 200 KB total, else `chat_error`); run via `AgentRunner` with `trigger vscode`; stream `chat_delta`; finish `chat_done` (cost, `pipelineConfirmation` when the run awaits approval).
4. `chat_confirm_pipeline` → `agents.confirmPipeline` path; result reported via `chat_done`/`chat_error`.
5. All inbound frames zod-validated; invalid → `chat_error` with `ref`, connection kept.

## Tests
Bridge unit tests: v1 and v2 hello, v1 client never receives chat frames; chat service with fake runner: new conversation, attachment limit, project resolution failure, pipeline confirmation round trip. Integration `TC-M12-040` WebSocket v2 client in the harness sends `chat_send` → receives deltas + done.
