# M10-06 — Code pipeline as an agent team (PM / Coder / QA agents)

Milestone: M10 · Depends on: M10-01 · Role: Implementer · Size M · **Deps pre-installed**
Requirements: FR-AG-12 · ARCH §15.1 (team workflow), §8

## Goal
The existing code pipeline takes its model ladders from the built-in PM, Coder and QA agents, so the owner configures models in one place (Agents). Pipeline behaviour is unchanged.

## Read first
ARCH §8, SRS v2 §3.1, `services/{pipeline-orchestrator,role-caller,settings-service,agent-registry}.ts`, `domain/default-settings.ts`, Settings UI `apps/desktop/src/features/settings/**` (pipeline role section), M6 tests.

## Scope
- `services/pipeline-orchestrator.ts`, `services/role-caller.ts` (resolve ladders via a new `IRoleLadderSource`), `services/agent-registry.ts` (method `ladderForRole(role)`), `services/settings-migrations.ts` (new, + test) — one-time copy of `settings.pipeline.roleAssignment` into the PM/Coder/QA built-in agents' ladders **only if the user changed it from defaults** (built-in rule: the migration is the single code path allowed to write a built-in's ladder; record `migrations.roleAssignmentToAgents=true` in settings meta)
- Desktop: the Settings → Pipeline "Role assignment" block becomes read-only, showing the three agents' ladders with an "Edit in Agents" link (link target added in M10-07; until then a no-op button with the same label)
- i18n keys (en, vi)

## Requirements
1. `RoleCaller` gets ladders: PM ← agent `agent-pm`, Coder ← `agent-coder`, Reviewer ← `agent-qa` (disabled agent → fall back to `settings.pipeline.roleAssignment` and log `warn`).
2. Prompts, stage machine, verdict rule, fix-round limit, cost attribution (`pipeline_*` purposes) unchanged.
3. `settings.pipeline.roleAssignment` stays in the schema (backward compatibility) but is no longer edited by the UI.
4. Migration idempotent; runs at container start after seeding.

## Tests
Unit: ladder resolution incl. disabled agent fallback; migration (defaults → no change, custom → copied, second run no-op). Regression: full M6 unit suite + integration pipeline tests green (QA runs `apps/sidecar/test/integration/pipeline*.test.ts`). UI component test for the read-only block.

## Acceptance criteria
- [ ] typecheck/lint/test green; M6 regression green in integration (QA). No E2E.
