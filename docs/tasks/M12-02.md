# M12-02 — ChannelService and `channels.*` RPC (accounts, sync, messages)

Milestone: M12 · Depends on: M12-01 · Role: Implementer · Size M · **Deps pre-installed**
Requirements: FR-CH-02, FR-CH-03, NFR-V2-01 · D21

## Scope
- `apps/sidecar/src/services/channel-service.ts` (+ test), validators `validation/channels.ts`, `container.ts`, `src/types/schemas.ts` RPC `channels.listAccounts|updateAccount|disconnect|sync|listMessages` + notification `channels.synced`
- integration `apps/sidecar/test/integration/channels.test.ts` (uses the fake adapter; create the account through a test-only helper in the harness, since connect flows arrive in M13/M14)

## Requirements
1. `sync(accountId)`: account connected (else `CHANNEL_AUTH`); single-flight per account (concurrent callers share one promise); calls `adapter.sync(account, cursor)`; inserts messages (triage `untriaged`); saves `nextCursor` and `lastSyncedAt` only on success; emits `channels.synced`. No LLM, no ledger rows.
2. No timers anywhere in the service (lint-level check: a unit test asserts the service module does not reference `setInterval`).
3. `updateAccount`: `projectId` must exist; `defaultAgentId` must exist and include the account's channel; `commandSenders` valid emails (≤ 20).
4. `disconnect`: adapter disconnect (best effort) → delete keychain entry `itstudio-channel/<id>` → `connected=false` (messages kept).
5. `listMessages`: newest first, filter by triage, cursor paging, never returns tokens.

## Tests
Unit: single-flight, cursor persistence on failure, validation; integration `TC-M12-001` sync twice → no duplicates, `TC-M12-002` idle app 10 min (fake clock) → adapter `sync` call count 0.
