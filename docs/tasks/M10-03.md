## Goal
Chatting in a conversation bound to an agent runs that agent: its persona, its model ladder, its tools (with the loop limit) — recorded as an `AgentRun` whose cost is visible in P&L under purpose `agent`.

## Contracts
```ts
interface IAgentRunner {
  run(input: AgentInput, trigger: AgentRun['trigger'], opts: { stream: boolean; onDelta?: (t: string) => void },
      signal: AbortSignal): Promise<Result<{ run: AgentRun; message: ChatMessage }>>;
  cancel(runId: AgentRunId): Promise<Result<AgentRun>>;
}
```

## Requirements
1. Flow (ARCH §15.2): create run `running` → BudgetGuard → context = agent persona + `agent-common` rules + (memory block placeholder: empty until M11-04) + RAG hits if the conversation has RAG on + history (newest first until 60 % of the smallest context window in the ladder, estimated with `token-estimate`) → router with `ladderOverride = agent.modelLadder`, `purpose = agent`, tools = registry declarations for `allowedTools(...)`, `agentRunId` on the request (add optional `agentRunId` to the internal router request → ledger).
2. Tool loop: when the response has tool calls → `checkToolCall` → parse → execute → append `tool_result` → next router call; stop after 6 executed calls (FR-AG-07: the 7th call is answered with an error result and the model gets one final turn without tools). Cancel aborts router + tool `AbortSignal`.
3. Run cost = sum of ledger rows with this `agentRunId` (MoneyDisplay); persisted on finish.
4. State changes via the pure `agent-run-machine` (SRS §7.1; illegal → `CONFLICT`); every change emits `agent.run`.
5. Chat integration: `chat.send` on an agent-bound conversation uses the runner; UI keeps receiving `chat.delta/completed/failed` with the same `requestId` semantics; the stored assistant message gets `modelKey`, usage and parts (tool calls/results stored as parts). Unbound conversations behave exactly as v1 (regression tests stay green).
6. `chat.setAgent` validates agent exists & enabled; `null` unbinds. New conversations get the project default agent (M10-01) unless `chat.createConversation` passes none — add optional `agentId?` param (additive).
7. Agent deleted/disabled while bound → next send fails `VALIDATION` "This agent is no longer available — pick another agent" (no silent fallback).
