## Schema additions (copy exactly)
In §6 after `ProjectPnL`:
```ts
export interface PortfolioPnL {
  readonly from: IsoDateTime;
  readonly to: IsoDateTime;
  /** One entry per project (including projects with no activity), ordered by margin ascending (worst first). */
  readonly projects: readonly ProjectPnL[];
  readonly revenue: MoneyDisplay;
  readonly cost: MoneyDisplay;
  readonly margin: MoneyDisplay;
  readonly marginPercent: number | null;
  /** Cost per project; `key` = projectId. Sorted by cost descending. */
  readonly byProject: readonly CostBreakdownRow[];
  /** Cost per model across all projects. Sorted by cost descending. */
  readonly byModel: readonly CostBreakdownRow[];
}
```
In `RpcMethodMap` next to `pnl.get` / `revenue.add`:
```ts
'pnl.getAll': { params: { readonly from: IsoDateTime; readonly to: IsoDateTime }; result: PortfolioPnL };
'revenue.list': { params: { readonly projectId: ProjectId; readonly from: IsoDateTime; readonly to: IsoDateTime }; result: readonly RevenueEntry[] };
```

## Requirements
1. `revenue.add`: validate `amount` finite and > 0, `description` 0–500 chars (trimmed). USD → `round(amount × 1e6)` µUSD; VND → `round(amount / usdToVnd × 1e6)` µUSD using the effective FX rate (override if set, else fetched). Use bigint-safe helpers from `domain/money.ts`; no float accumulation. Unknown project → `NOT_FOUND`. `occurredAt` = clock now. Persist and return the entry.
2. `revenue.list`: entries in `[from, to)`, newest first.
3. `pnl.get`: revenue sum + ledger cost sum over `[from, to)`; `margin = revenue − cost` (may be negative); `marginPercent = margin / revenue` (null when revenue = 0, rounded to 4 decimals); `byModel` (key = modelKey), `byPurpose` (key = purpose), `byDay` (key = UTC `YYYY-MM-DD`, every day with activity, ascending) — sorted by cost descending for model/purpose. All money fields as `MoneyDisplay` built by the existing sidecar money formatter with the current FX rate.
4. `pnl.getAll`: one `ProjectPnL` per existing project + portfolio totals and `byProject` / `byModel` as specified above. Totals must equal the sum of the per-project numbers exactly (integer µUSD).
5. Aggregation math lives in pure `domain/pnl.ts` (input: rows; output: totals/breakdowns in µUSD) — services only fetch rows and format. `from >= to` → `VALIDATION`.

## Tests
- Pure: hand-computed oracle with ≥ 3 models, 2 purposes, entries on 3 UTC days including one at 23:59:59.999Z and one at 00:00:00.000Z (boundary), negative margin, zero revenue → `marginPercent` null; portfolio totals = sum of projects.
- Revenue: USD/VND conversion incl. FX override, rounding (e.g. 1 VND at 25 000 = 40 µUSD), invalid amount (0, negative, NaN, Infinity) → `VALIDATION`, unknown project → `NOT_FOUND`.
- Integration `TC-M3-040`: two projects, scripted chat calls create ledger rows, `revenue.add` in VND and USD → `pnl.get` and `pnl.getAll` match the oracle; IPC validators reject bad params.
