## Scope
- `src/types/schemas.ts` — **additive**: `RpcMethodMap` entries `'workflow.graph': { params: { readonly projectId: ProjectId | null }; result: WorkflowGraph }` and `'workflow.activity': { params: { readonly projectId: ProjectId | null; readonly moduleId?: WorkflowModuleId; readonly limit: number; readonly before?: IsoDateTime }; result: readonly ActivityEvent[] }`; `RpcNotificationMap` entry `'workflow.activity': readonly ActivityEvent[]`.
- `apps/sidecar/src/validation/**` (validators), `apps/sidecar/src/domain/workflow-topology.ts` (+ test), `apps/sidecar/src/services/activity-recorder.ts` (+ test), `apps/sidecar/src/infra/sqlite/{schema.ts,activity-repository.ts}` + migration (**do not hand-write**; QA generates), `apps/sidecar/src/container.ts` (construct, subscribe, 2 `server.register` lines), integration test `apps/sidecar/test/integration/workflow.test.ts`.

## Requirements
1. `workflow-topology.ts` (pure): the full node / lane / edge catalogue of ARCH §13.1; every edge has a `contract` naming a schema type; a function marks nodes `disabled` from settings (VS Code bridge off, image generation disabled).
2. `activity-recorder.ts`: subscribe to the in-process events listed in §13.1 and map each to `ActivityEvent` (module, edge, kind, **redacted** summary — never prompt / message / document text or keys — refs, durationMs, cost as `MoneyDisplay`); maintain per-module in-flight sets (start / complete pairs) and 24 h counters; batch the `workflow.activity` notification (≤ 4 per second per project).
3. Storage: `activity_events` table; in-memory ring (500 per project); retention 7 days or 20 000 rows per project — prune at startup and hourly (timer `unref`, stopped on shutdown).
4. RPC `workflow.graph` (`projectId: null` = aggregate) and `workflow.activity` (limit 1–200, newest first, `before` cursor).
5. A pure mapping table tested case by case (source event → module / edge / kind); a redaction corpus test (prompt text, API-key-like strings never appear in any summary).
