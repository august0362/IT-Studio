# M6-02 — WriteTransaction: journaled atomic multi-file write, rollback, crash recovery

Milestone: M6 · Depends on: M6-01 · Role: Implementer (ROLES §1.3) · **Deps pre-installed** · Safety-critical → **100 % branch coverage** (TESTING.md §4)

## Goal
The Worker applies a set of `FileOperation`s all-or-nothing, can restore the exact previous state on any failure, and recovers interrupted transactions on startup (ARCH §9.2–§9.4, D11).

## Requirements
1. `prepare(projectRoot, ops, allowedPaths)`: every path through `resolveSafe`; for `replace|patch|delete|rename` verify current file `sha256 === baseHash` (mismatch → `PATCH_CONFLICT`, nothing written); `create` must not overwrite an existing file (`CONFLICT`); apply unified diffs in memory (`domain/unified-diff.ts`: standard `@@ -a,b +c,d @@` hunks, exact context match, reject fuzz → `PATCH_CONFLICT`); write journal `.itstudio/tx/<id>/manifest.json` (status `prepared`, ops, original existence + hashes) and copy originals to `.itstudio/tx/<id>/orig/<path>`; fsync files and the manifest.
2. `commit()`: per op write `<path>.itstudio-tmp` → fsync → rename over target; renames/deletes last; manifest → `committed`.
3. `markValidated()`: manifest → `validated`, delete `orig/` (manifest kept; purge > 7 days handled by recovery service).
4. `rollback()`: restore every original, delete files that did not exist, revert renames, verify hashes, manifest → `rolled_back`; any step failing → `ROLLBACK_FAILED` with `remediation` listing exact journal paths.
5. `journal-recovery.ts`: on startup scan `<projectRoot>/.itstudio/tx/*/manifest.json`; `prepared|committed` → rollback; report recovered count; purge validated manifests older than 7 days (injected clock).
6. Journal access bypasses the `.itstudio/**` forbidden rule only through this module (explicit internal API, not via `resolveSafe`).

## Tests (memory FS with fault injection)
- Happy path for each op kind; mixed batch; baseHash mismatch → nothing written; patch with wrong context; create-over-existing.
- **Fault injection** at every step (after N writes, during rename, during manifest write) → rollback restores byte-identical originals (hash compare of the whole tree).
- Crash simulation: prepared/committed manifests on disk → recovery restores state; validated → untouched; purge by age.
- Rollback failure path → `ROLLBACK_FAILED` with journal paths.
- 100 % branch coverage for `write-transaction.ts` and `unified-diff.ts`.
