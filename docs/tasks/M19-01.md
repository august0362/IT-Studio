# M19-01 — SystemActionService: per-OS reboot / shutdown, `sudo -n`, audit log

Milestone: M19 · Depends on: M19-00 · Role: Implementer · Size M · **Deps pre-installed**
Requirements: FR-SA-01, FR-SA-02 (server-side check), FR-SA-03, FR-SA-04 (manager part) · ARCH §22

## Scope
`apps/sidecar/src/services/system-action-service.ts` (+ test), `domain/sudo-error.ts` (+ test: classify outputs), `ports/server-action-repository.ts`, `infra/sqlite/server-action-repository.ts` (+ test), `infra/sqlite/schema.ts` (`server_actions`; migration by QA), catalog entries, `ssh-connection-manager.ts` (rebooting state + 10 min tracking), `src/types/schemas.ts` RPC `server.action`, `server.listActions` + validators, `container.ts`, integration `apps/sidecar/test/integration/system-actions.test.ts`.

## Requirements
1. `confirmName` must equal the server name exactly (case-sensitive) else `VALIDATION`; OS `unknown` → `VALIDATION` "Set the OS first".
2. Execute the catalog command (consumer `action`); success conditions: exit 0, **or** the connection drops within 10 s after start (reboot/shutdown kill the session) → ok.
3. `sudo: a password is required` / `sudo: a terminal is required` / exit 1 with `sudo:` prefix → `SUDO_REQUIRED` with the OS-specific sudoers line filled with the username; Windows "Access is denied" → `VALIDATION` with remediation "Use an administrator account".
4. Audit row for every attempt (ok/failed), including validation failures after the name check passes.
5. Reboot ok → manager state `rebooting`; reconnect attempts every 10 s until online (emit "back online after mm:ss" note) or 10 min → `offline` with remediation. Shutdown ok → `offline`, no reconnects until the user clicks Connect.

## Tests
Sudo classifier corpus; service: name mismatch, unknown OS, each OS command chosen correctly, connection-drop success, failure classes, audit rows; manager rebooting timeline with fake timers. Integration `TC-M19-001` reboot on the fake server (server closes the connection, comes back after 20 s).
