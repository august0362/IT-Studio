Milestone: M17 · Depends on: M17-00 · Role: Implementer · Size M · **Deps pre-installed**

## Scope
- `apps/sidecar/src/services/docker/docker-manager.ts` (+ test), `services/docker/dial-stdio-agent.ts` (+ test: `http.Agent` subclass whose `createConnection` opens an SSH exec channel running the catalog command `docker_dial_stdio` and returns it as a duplex socket), catalog entries `docker_dial_stdio` (`docker system dial-stdio`) per OS
- `apps/sidecar/test/support/fake-docker-engine.ts` + fake SSH server hook for `dial-stdio`
- `src/types/schemas.ts` (none yet besides `dockerAvailable` on `ServerStatus` already present), remediation `DOCKER_UNAVAILABLE`, `container.ts`

## Requirements
1. One `Dockerode` instance per server, created lazily, using the agent (`protocol: 'http'`, host `docker`); acquires SSH consumer `docker` while any Docker operation/stream/watch is active, releases afterwards.
2. Availability: `ping()` + `version()`; failure classes: exec exit "command not found" / non-zero with "permission denied" / timeout → `dockerAvailable=false`, `DOCKER_UNAVAILABLE` with specific remediation (install CLI ≥ 18.09; `sudo usermod -aG docker <user>` then reconnect; start Docker Desktop on macOS/Windows). Cached until reconnect or explicit re-check.
3. Requests time out (30 s default, logs/events exempt); errors mapped to `AppError` (`NOT_FOUND` for 404 container, `CONFLICT` for 304/409, else `INTERNAL` with safe message).

## Tests
Agent with fake engine through fake SSH server: ping, version, multiple sequential requests (new channel per connection or keep-alive — document choice), failure classes, consumer ref counting.
