# UX-02 — Pipeline: fail fast with clear messages when a role has no usable model

Milestone: v1 owner feedback · Depends on: — · Role: Implementer (ROLES §1.3) · Size M · **Deps pre-installed**

## Problem (reported by the owner, 2026-10-04)
With only a Google key configured, a Code pipeline run failed at SPECIFYING with:
`LADDER_EXHAUSTED — anthropic/claude-opus-5-5: capability_mismatch; anthropic/claude-sonnet-5-5: capability_mismatch; openai/gpt-5.5: capability_mismatch` and the report said "Thay đổi không gian làm việc chưa được hoàn tác" ("workspace changes were not rolled back").
Three problems: (1) `capability_mismatch` is reported when the real cause is **no API key** for the provider; (2) the run started although no model in the PM ladder was usable; (3) the rollback line is alarming although nothing was written (failure before WRITING).

## Requirements
1. **Distinguish skip reasons.** When the router skips a model because the provider has no stored key, the attempt records `skipReason: 'no_api_key'` (failure kind stays `capability_mismatch` for compatibility); missing capability → `missing_capability`; disabled model → `disabled`; open circuit → `circuit_open`. The `LADDER_EXHAUSTED` message lists models grouped by reason in plain words, e.g. "No API key: Anthropic (claude-opus-5-5, claude-sonnet-5-5), OpenAI (gpt-5.5)".
2. **Remediation for `LADDER_EXHAUSTED`** is concrete: if any skip was `no_api_key` → "Add an API key in Settings → API Keys for: Anthropic, OpenAI" **and** "Or add a model from a provider you have a key for (e.g. Google) to this role in Settings → Pipeline" (list the configured providers' enabled chat+json models, max 3, by name).
3. **Pre-flight at `pipeline.start`:** before creating the run, for each role (pm, coder, reviewer) check that at least one ladder model is enabled, has a key and has the required capabilities. If a role has none → reject `pipeline.start` with `VALIDATION` naming the role(s) and the same remediation as (2); no run row, no LLM call.
4. **Failure report wording:** when the failure happened before WRITING (nothing written), show "Nothing was written to your project." (vi: "Chưa có thay đổi nào được ghi vào dự án.") instead of the rolled-back / not-rolled-back line. Keep the existing lines for failures during/after WRITING.
5. The Code tab shows the pre-flight `VALIDATION` error with remediation in the existing `<ErrorPanel>` and a button "Open Settings → Pipeline" (navigation intent / existing settings navigation).
6. No change to fallback behaviour itself.

## Tests
Router: skip reasons for no key / missing capability / disabled / circuit; message grouping. Orchestrator: pre-flight reject per role, accepted when one model per role is usable, no LLM call on reject. Report builder: pre-WRITING wording vs WRITING/VALIDATING wording. UI component tests for the panel text and settings button.
