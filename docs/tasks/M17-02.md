# M17-02 — Containers: list, inspect, start / stop / restart, events → refresh & alerts

Milestone: M17 · Depends on: M17-01 · Role: Implementer · Size M · **Deps pre-installed**
Requirements: FR-DK-03, FR-DK-04 · ARCH §20

## Scope
`services/docker/container-service.ts` (+ test), `services/docker/docker-events.ts` (+ test), `domain/container-id.ts` (+ test), `src/types/schemas.ts` RPC `docker.list|inspect|action|watch|unwatch` + notification `docker.changed`, validators, `container.ts`, alert service hook (`container_exited`), integration `apps/sidecar/test/integration/docker.test.ts`.

## Requirements
1. Map Docker API to `ContainerInfo` (name without leading `/`, ports dedupe, `createdAt` ISO); inspect returns env **names only** (values redacted: `KEY=***`), mounts `source → destination`, restart count.
2. Actions validate id (`^[a-f0-9]{12,64}$`), stop timeout 10 s; return refreshed info; user-initiated actions are remembered for 30 s so their `die` events do not raise alerts.
3. Events stream (filters type=container, events start/stop/die/restart) open while `docker.watch` refs > 0 **or** background monitoring is on; reconnect with backoff; emit `docker.changed`; `die` with exitCode ≠ 0 and not user-initiated → alert `container_exited` (message includes container name and exit code); `start` resolves it.
4. Watch registry by view id (like metrics).

## Tests
Fake engine: list/inspect mapping, env redaction, action happy path + 404 + 304, events → changed + alert rules (user-initiated suppressed), stream reconnect. Integration `TC-M17-010` list + restart via RPC.
