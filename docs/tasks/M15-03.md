## Contracts
```ts
type SshConsumer = 'probe' | 'metrics' | 'docker' | 'sftp' | 'logs' | 'action';
interface ISshConnectionManager {
  acquire(serverId: ServerId, consumer: SshConsumer): Promise<Result<SshSession>>; // resolves when online
  release(serverId: ServerId, consumer: SshConsumer): void;
  exec(serverId: ServerId, command: RemoteCommand, opts: { timeoutMs: number; signal?: AbortSignal }): Promise<Result<{ stdout: string; stderr: string; code: number | null }>>;
  status(serverId: ServerId): ServerStatus;
  closeAll(): Promise<void>;
}
// RemoteCommand is the catalog type from M15-04; until then accept a branded constant string type.
```

## Requirements
1. Pure machine per SRS §7.1 (host-key branches stubbed to "pinned & equal" until M15-04 wires TOFU — keep the transitions in the table now).
2. One `ssh2` client per server; reference counting per consumer kind (counts, not booleans); idle close 60 s after the last release (injected clock/timers); keepalive 15 s ×3; `readyTimeout` 15 s.
3. Reconnect backoff 1→60 s with ±20 % jitter while refs > 0; stop when refs reach 0; `server.status` emitted on every state change (no duplicates).
4. Auth via key vault `withPrivateKey` (key buffer passed to ssh2 and zeroed after `ready`/`error`).
5. `exec` timeout kills the channel (`signal('KILL')` + close) and returns `SSH_UNREACHABLE`-class timeout error; stdout/stderr capped at 1 MB each.
6. Shutdown (`system.shutdown`) closes all connections within 2 s.
