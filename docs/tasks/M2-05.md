# M2-05 — Model registry + provider registry + `models.list`

Milestone: M2 · Depends on: M1-05, M2-02 · Role: Implementer (ROLES §1.3) · **Deps pre-installed**

## Goal
The sidecar knows every model (from seeds, persisted), which provider adapter serves it, and whether the provider has a key — so the router (M2-07) can compute eligibility.

## Read first
- `AGENTS.md`, CONTEXT D15 + Q-02, `ARCHITECTURE.md` §5.1, §5.3 (eligibility), `config/README.md`, `apps/sidecar/src/config/load-seeds.ts`, `apps/sidecar/src/ports/llm-provider.ts`

## Scope — files you may create/modify
- `apps/sidecar/src/services/model-registry.ts`, `apps/sidecar/src/providers/provider-registry.ts`, tests
- `apps/sidecar/src/container.ts` (wire + register `models.list`)
- Adapters for providers not yet implemented (OpenAI-compatible, Google) are registered via a factory map that tolerates missing modules: register only adapters that exist in `providers/`; missing ones mark their models `enabled: false` with reason `adapter_unavailable` in an internal status map (do not change `ModelDescriptor` shape).

## Requirements
1. `ProviderRegistry`: `get(id: ProviderId): ILlmProvider | undefined` (Factory pattern, CONVENTIONS §3.1).
2. `ModelRegistry`: `list(): readonly ModelDescriptor[]`, `get(key)`, `supports(key, caps)`; source = seeds at startup (persisting overrides is out of scope).
3. `eligibility(key, required: ModelCapability[], hasSecret: (p) => boolean): { eligible: boolean; reason?: 'disabled' | 'no_secret' | 'capability' | 'adapter_unavailable' | 'unknown_model' }`.
4. `verifyModelIds(provider, apiKey)`: calls `listModels` and returns `{ known: string[]; missing: string[] }` for seed models of that provider — used later by the Architect to resolve Q-02 when keys exist; expose as internal service method only (no RPC).
5. RPC `models.list` → `ModelDescriptor[]`.
