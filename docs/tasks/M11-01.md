# M11-01 — Memory store: SQLite metadata + LanceDB vectors

Milestone: M11 · Depends on: M11-00 · Role: Implementer · Size L · **Deps pre-installed**
Requirements: FR-MEM-01 · DD-V2-04 · ARCH §16.1

## Goal
A repository-backed memory store that keeps `MemoryItem` metadata in SQLite and vectors in a per-agent LanceDB table, with similarity search scoped by agent and project.

## Read first
SRS v2 §3.2, §5 (`memories`, LanceDB `memories_<agentId>`), `schemas.ts` §15, `ports/vector-store.ts`, `infra/lancedb/**` (explicit Arrow schema — BUG-M5-001), `services/embedding-dispatcher.ts`.

## Scope
- `apps/sidecar/src/ports/memory-store.ts`, `infra/sqlite/memory-repository.ts` (+ test), `infra/sqlite/schema.ts` (`memories`; migration by QA), `infra/lancedb/memory-vector-store.ts` (+ test), `infra/memory-memory-vector-store.ts` (in-memory fake for tests/E2E), `services/memory-store.ts` (+ test), `container.ts`

## Contracts
```ts
interface IMemoryStore {
  insert(item: MemoryItem, vector: Float32Array): Promise<Result<void>>;
  update(item: MemoryItem, vector?: Float32Array): Promise<Result<void>>;
  delete(id: MemoryId): Promise<Result<void>>;
  deleteAllForAgent(agentId: AgentId): Promise<Result<number>>;
  get(id: MemoryId): Promise<Result<MemoryItem>>;
  list(q: { agentId?: AgentId; projectId?: ProjectId | null; kinds?: readonly MemoryKind[]; text?: string; limit: number; cursor?: string }): Promise<Result<Page<MemoryItem>>>;
  similar(q: { agentId: AgentId; projectIds: readonly (ProjectId | null)[]; vector: Float32Array; topK: number }): Promise<Result<readonly { item: MemoryItem; cosine: number }[]>>;
  repair(): Promise<Result<{ removedOrphanVectors: number; missingVectors: readonly MemoryId[] }>>;
}
```

## Requirements
1. Writes: SQLite first, then LanceDB; if LanceDB fails, the SQLite row is kept and listed by `repair()` as missing vector (DD-V2-04). Deletes: LanceDB then SQLite (orphans removed by repair).
2. `similar` filters by agent and the given project ids (`null` = global) and returns cosine in [0,1]; expired items excluded.
3. Table per agent created lazily with dimension from `settings.rag.embedding.dimensions`; dimension mismatch → `VALIDATION` "re-embed required" (handled by cleanup in M11-06).
4. Text ≤ 500 chars enforced at store level (`VALIDATION`).

## Tests
Repo + vector store on temp dirs; consistency on simulated LanceDB failure; scope filtering; expiry; repair. Fake store passes the same contract test.
