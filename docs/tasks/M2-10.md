The backend for the Chat tab: persistent conversations/messages per project, `chat.send` streaming through `LlmRouter` with fallback, per-message cost, cancel.

## Requirements
1. Tables: `conversations (id, project_id, title, rag_enabled, created_at, updated_at)` with FK to projects; `messages (id, conversation_id, role, parts_json, model_key, usage_json, created_at)` indexed by `(conversation_id, created_at)`. Parts JSON validated with existing zod schemas on read.
2. RPC: `chat.listConversations`, `chat.createConversation` (default title "New chat"), `chat.getMessages`, `chat.send`, `chat.cancel`.
3. `chat.send`: persist the user message, return `{requestId, userMessageId}` immediately; run in background: build `LlmRequest` (system prompt ROLES §2.6 without the RAG block — RAG wiring lands in M5-06; history = last 20 messages, token-capped at ~12k estimated tokens, oldest dropped first; `purpose: chat`; `modelOverride` → `ladderOverride: [modelOverride]`), call `LlmRouter.dispatch` with `onDelta` → `chat.delta`, `onReset` → publish `router.event` already handled by router (UI clears partial); on success persist assistant message (`modelKey`, `usage`) and publish `chat.completed` with `cost: MoneyDisplay` computed via `domain/cost.ts` + current seed price table + FX seed (`domain/money.ts`); on failure publish `chat.failed` with the `AppError` (remediation included).
4. `chat.cancel(requestId)` aborts the in-flight dispatch → `chat.failed` with `CANCELLED`; returns `{cancelled: true|false}`.
5. Auto-title: after the first assistant reply, set the title to the first 60 chars of the first user message (no LLM call — D21 token rule).
6. Concurrency: multiple conversations may stream concurrently; one in-flight request per conversation (second `chat.send` while busy → `CONFLICT`).
