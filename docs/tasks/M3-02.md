# M3-02 — Ledger: append-only cost records from every router completion

Milestone: M3 · Depends on: M2-07, M3-01, M2-10 · Role: Implementer (ROLES §1.3) · **Deps pre-installed**

## Goal
Every billed provider call (success or billed failure) becomes one immutable `LedgerEntry` with cost frozen at write time, pushed live to the UI and queryable with paging (D6, ARCH §1 principle 5, §6.1).

## Read first
- `AGENTS.md`, `ARCHITECTURE.md` §6.1, §6.5, `schemas.ts` §6 (`LedgerEntry`, `LedgerQuery`, `Page`, `MoneyDisplay`), §10 (`ledger.query`, `ledger.entry`), `apps/sidecar/src/services/llm-router.ts` (`RouterCompleted` event), `apps/sidecar/src/domain/cost.ts`, `domain/money.ts`, `config/pricing.seed.json`, `config/fx.json`

## Scope
- `apps/sidecar/src/infra/sqlite/schema.ts` (+ `ledger_entries` table, index `(project_id, occurred_at)`) + drizzle migration (`npm run db:generate -w @itstudio/sidecar`; if blocked, note it — QA regenerates; **do not hand-write**)
- `apps/sidecar/src/ports/ledger-repository.ts`, `apps/sidecar/src/infra/sqlite/ledger-repository.ts`, `apps/sidecar/src/services/ledger-service.ts`, `apps/sidecar/src/services/price-source.ts` (temporary: serves the seed `PriceTable` + seed FX until M3-03/M3-05), `apps/sidecar/src/container.ts`, tests; `apps/sidecar/src/services/chat-service.ts` only to replace its local cost computation with `LedgerService` / `PriceSource` (single source of cost)

## Requirements
1. Repository is **append-only** (insert + queries only; no update/delete methods). Rows store the `priceTableVersion` used.
2. `LedgerService` subscribes to `RouterCompleted`: computes cost with `computeTokenCost(usage, price)`; unknown model price → cost 0 + emits a warning once per model (log + `pricing.updated` is NOT available yet → log only); writes the row (`billedFailure` from the event); publishes `ledger.entry` `{entry, cost: MoneyDisplay}`.
3. Attribution: `projectId`, `purpose`, `llmRequestId`, `conversationId`/`pipelineRunId` when present on the request.
4. `ledger.query(LedgerQuery)` → `Page<LedgerEntry>`: filters (from/to/purposes/modelKeys), newest first, opaque cursor (base64 of `occurredAt|id`), `limit` 1..500.
5. `ChatService` stops computing cost itself and uses the ledger-recorded cost for `chat.completed`.

## Tests
- Append-only guarantee (no mutating API); cost frozen even if the price source later changes; billed failure row; unknown price → 0 + single warning; cursor paging (stable across inserts), filters; `ledger.entry` published once per completion.
- Integration case `TC-M3-001` in `apps/sidecar/test/integration/ledger.test.ts`: a scripted chat produces exactly one ledger row visible through `ledger.query` over real stdio.
