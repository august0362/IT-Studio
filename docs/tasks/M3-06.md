# M3-06 — BudgetGuard: budgets, warning thresholds, optional Hard Stop

Milestone: M3 · Depends on: M3-02, M3-03, M2-07 · Role: Implementer (ROLES §1.3) · **Deps pre-installed**

## Goal
Replace the always-ok budget guard with the real one: per-project budgets (daily/monthly/lifetime), warnings at thresholds, and a Hard Stop that blocks paid calls when enabled (D7, ARCH §6.4).

## Read first

## Scope
- schema (+ `budgets`, `budget_alerts` tables) + drizzle migration (**do not hand-write**), `apps/sidecar/src/ports/budget-repository.ts`, `apps/sidecar/src/infra/sqlite/budget-repository.ts`, `apps/sidecar/src/services/budget-guard.ts` (+ test), `apps/sidecar/src/domain/budget.ts` (+ test: pure level/period math), `apps/sidecar/src/container.ts` (swap the always-ok guard), integration test `apps/sidecar/test/integration/budget.test.ts`

## Requirements
1. `domain/budget.ts` (pure): period window from `now` (UTC day; calendar month; lifetime), `fractionUsed`, `level` (`ok` < first threshold ≤ `warning` < 1.0 ≤ `exceeded`), crossed thresholds since last alert.
2. `BudgetGuard.check(projectId, estimate)`: spent = ledger sum in each budget's window (+ the estimate for exceed check); for every crossed threshold not yet alerted in this window → persist alert + publish `budget.alert` (`BudgetStatus`) **once per threshold per window**; if any budget would be `exceeded` and `settings.budget.hardStop` → `{blocking: true}` → router fails with `BUDGET_HARD_STOP` (remediation: "Raise the budget in Cost & P&L or turn off Hard Stop in Settings").
3. Hard Stop OFF (default): never blocks; still alerts.
4. RPC `budget.set(Budget)` (validates `warnAt` ascending in (0,1], limit > 0; upsert by `projectId+period`) → `BudgetStatus`; `budget.status({projectId})` → all budgets of the project.
5. Embedding and pricing-extraction calls go through the same guard (they use the router/dispatcher completion path; ensure the dispatcher calls the guard too — minimal change in `embedding-dispatcher.ts` allowed).

## Tests
