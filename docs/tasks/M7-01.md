# M7-01 — VS Code extension: activation, session discovery, WebSocket client, status bar

Milestone: M7 · Depends on: M0-04 · Role: Implementer (ROLES §1.3) · **Deps pre-installed** (no new packages: use the global `WebSocket` available in VS Code's Node runtime)

## Goal
The companion extension activates in an IT Studio project, reads `.itstudio/session.json`, connects to the sidecar's loopback WebSocket, performs the `ExtHello` handshake, reconnects on loss, and shows connection state in the status bar. (The sidecar server side is M7-02; test against a fake.)

## Scope — files you may create/modify
- `apps/vscode-ext/src/**`, `apps/vscode-ext/package.json` (contributes/activationEvents only — no dependency changes)

## Requirements
1. `src/session.ts`: `readSession(workspaceRoot, fs)` → `Result<{ port: number; token: string; protocolVersion: 1 }>`; validates shape (hand-written type guards, no zod in the extension), port 1–65535, token 64 hex chars. Injected fs for tests.
2. `src/bridge.ts`: `class SidecarBridge` with injected `createSocket(url) => WebSocketLike`, `clock` and `logger`:
   - connects to `ws://127.0.0.1:<port>`; on open sends `ExtHello{type:'hello', protocolVersion:1, token, workspaceRoot, extensionVersion}`;
   - waits for `welcome` (5 s timeout) → state `connected`; responds to `ping` with `pong`; dispatches other `SidecarToExt` messages to registered handlers (handlers for reveal/show_diff/notify are stubs that log — implemented in M7-04);
   - on close/error: state `disconnected`, reconnect with backoff 1, 2, 4, 8, 15 s (cap); re-reads `session.json` before each attempt (port/token rotate on sidecar restart);
   - `dispose()` stops reconnecting and closes the socket.
   - Validate every inbound message with a type guard; ignore unknown types; never `eval`.
3. `src/extension.ts`: `activate` finds the first workspace folder containing `.itstudio/session.json`, starts the bridge, watches the session file (FileSystemWatcher) to reconnect when it changes, and updates the status bar via `statusLabel` (`idle` / `connected` / `disconnected`); clicking the status item shows a quick pick with "Reconnect" and "Show log". Output channel "IT Studio" for logs (never log the token).
4. `package.json`: keep `activationEvents: ["workspaceContains:.itstudio/session.json"]`; add commands `itstudio.reconnect`, `itstudio.showLog`.
