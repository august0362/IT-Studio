## Goal
Agents exist as data: six built-in templates are seeded on first start, the user can create, clone, edit, enable/disable and delete custom agents through RPC, and each project can have a default agent.

## Contracts
`AgentDefinition`, `AgentTemplate`, `AgentToolName`, `ChannelKind`, `AgentMemoryPolicy` (schemas §14/§16). Repository port:
```ts
interface IAgentRepository {
  list(): Promise<Result<readonly AgentDefinition[]>>;
  get(id: AgentId): Promise<Result<AgentDefinition>>;           // NOT_FOUND
  insert(a: AgentDefinition): Promise<Result<void>>;            // CONFLICT on duplicate name
  update(a: AgentDefinition): Promise<Result<void>>;
  delete(id: AgentId): Promise<Result<void>>;
  getProjectDefault(p: ProjectId): Promise<Result<AgentId | null>>;
  setProjectDefault(p: ProjectId, a: AgentId | null): Promise<Result<void>>;
}
```

## Requirements
1. Seeding at container start: insert each seed agent whose id is missing; never update existing rows (idempotent; user edits on clones untouched; built-ins keep their seed body except `enabled`).
2. Validation (pure, `domain/agent-validation.ts`) exactly per FR-AG-03; returns all violations (`VALIDATION` with `details.fields`). Model checks use `ModelRegistry` (exists, enabled, `chat`; `tool_calling` if tools non-empty).
3. Built-ins: `update` allows only `enabled` (other fields → `VALIDATION` "Clone this agent to edit it"); `delete` → `VALIDATION`. Clone: new UUID, template preserved, `builtIn false`, name "<name> (copy)" (then " (copy 2)", …).
4. Deleting a custom agent that is a project default clears that default; conversations bound to it fall back to no agent (handled in M10-03 — here only clear defaults).
5. `agents.commonRules` returns the text from `prompts/agent-common.ts` (ROLES §2 common data rule + "Never include secrets" + tool guidance header).
6. Timestamps via `IClock`, ids via `IIdGenerator`.
