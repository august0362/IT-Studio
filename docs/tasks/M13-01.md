# M13-01 — Gmail OAuth (installed app, PKCE, loopback): connect / disconnect

Milestone: M13 · Depends on: M13-00 · Role: Implementer · Size L · **Deps pre-installed**
Requirements: FR-GM-01, FR-GM-02 · DD-V2-07 · ARCH §17.5

## Goal
The owner connects a Gmail account with their own Google OAuth client; the refresh token lands in the Windows keychain; nothing secret ever reaches the UI.

## Read first
SRS v2 §3.4, §6.3 (`gmail.beginConnect`, `gmail.connectStatus`), §6.4 (`gmail.connect`), §6.6, RFC 7636 (PKCE), RFC 8252 (loopback redirect), `ports/{secret-store,http-client}.ts`, `services/channel-service.ts`.

## Scope
- `apps/sidecar/src/domain/pkce.ts` (+ test), `apps/sidecar/src/infra/loopback-server.ts` (+ test; node `http`, bind `127.0.0.1`, port 0), `apps/sidecar/src/services/gmail/gmail-auth-service.ts` (+ test), `services/gmail/gmail-token-store.ts` (keychain JSON), validators, `container.ts`, `src/types/schemas.ts` (RPC + notification above)
- Desktop: `apps/desktop/src/features/inbox/ConnectGmailDialog.tsx` (+ test) — fields client id / optional secret, *Connect* opens `authUrl` with the opener plugin, polls nothing: waits for `gmail.connect` notification (and `gmail.connectStatus` once on reopen), shows result
- `docs/guides/gmail-setup.md` is **not** in scope (M13-07)

## Requirements
1. `beginConnect`: validate client id format (`*.apps.googleusercontent.com`); create verifier (43–128 chars, unreserved set) + S256 challenge + `state` (32 random bytes base64url); start loopback server; return auth URL with `response_type=code`, scopes `https://www.googleapis.com/auth/gmail.modify https://www.googleapis.com/auth/gmail.send openid email`, `access_type=offline`, `prompt=consent`, `redirect_uri=http://127.0.0.1:<port>/callback`.
2. Callback: only `GET /callback`; reject wrong `state` (400 page, flow `failed`); exchange code at the token endpoint (form POST, PKCE verifier); require `refresh_token`; read email via `users.getProfile`; create/update `ChannelAccount` (kind gmail, project from params, `commandSenders` default `[email]`), store `{refreshToken, clientId, clientSecret?}` in keychain `itstudio-channel/<accountId>`; respond with a plain "You can close this tab" page (no scripts); close server.
3. Timeout 5 min → `expired`; one flow at a time (new begin cancels the previous).
4. Access tokens kept in memory only (expiry tracked); `getAccessToken(accountId)` refreshes when < 60 s remain; refresh failure `invalid_grant` → account `connected=false` + `CHANNEL_AUTH`.
5. Disconnect: POST revoke (best effort, errors logged), delete keychain entry.
6. Logs never contain codes, tokens, verifier (extend pino redact paths).

## Tests
PKCE vectors (RFC 7636 appendix B), loopback: wrong path 404, wrong state, double callback, timeout (fake clock); auth service with msw token endpoint: success, missing refresh token, invalid_grant; redaction test on logged objects.
