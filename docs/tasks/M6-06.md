# M6-06 — FailureReportBuilder + remediation table for every ErrorCode

Milestone: M6 · Depends on: M6-02, M6-03 · Role: Implementer (ROLES §1.3) · **Deps pre-installed**

## Goal
Every failure that the user sees (pipeline rollback, router failure, budget stop, …) comes with clear, ordered next steps (D11, ARCH §8.2).

## Read first
- `AGENTS.md`, `ARCHITECTURE.md` §8.2, §9.3, `schemas.ts` §1 (`ErrorCode`, `AppError`), §8 (`FailureReport`, `PipelineStage`), §9 (`CommandRun`)

## Scope
- `apps/sidecar/src/domain/remediation.ts` (+ test), `apps/sidecar/src/services/failure-report-builder.ts` (+ test). No container changes (wired in M6-05).

## Requirements
1. `remediationFor(code: ErrorCode, context?)`: exhaustive `Record<ErrorCode, …>` (compile error if a code is missing) returning 1–4 imperative English steps; context-aware variants for `PATCH_CONFLICT` (file list), `COMMAND_FAILED` (command kind + first failing diagnostic), `ROLLBACK_FAILED` (journal path), `BUDGET_HARD_STOP`, `PROVIDER_AUTH` (provider), `LADDER_EXHAUSTED` (models tried).
2. `FailureReportBuilder.build({ runId?, stage, error, rolledBack, restoredSnapshot?, commandRuns?, logLines })` → `FailureReport`: `nextSteps` = error.remediation if present else `remediationFor`; `logExcerpt` = last 60 lines, each truncated to 300 chars, with secrets redacted using the same patterns as `scripts/scan-secrets.mjs` (port the regex list into `domain/redact.ts` and reuse) and absolute user paths shortened to `~`.
3. Pure/deterministic; no I/O.

## Tests
- Every ErrorCode has steps (iterate `Object.values(ErrorCode)`); context variants; redaction of each secret pattern; 60-line/300-char limits; rolledBack false/true wording.
