# M3-03 — Versioned price tables + `pricing.get` / `pricing.override`

Milestone: M3 · Depends on: M3-02 · Role: Implementer (ROLES §1.3) · **Deps pre-installed**

## Goal
Prices live in SQLite as immutable versions (seed → manual overrides → later manual refresh in M3-04), and the ledger always prices calls with the current version while past rows keep theirs (D9, ARCH §6.1–§6.2).

## Read first
- `AGENTS.md`, CONTEXT D9, `ARCHITECTURE.md` §6.1, §6.2 (step 5 precedence), `schemas.ts` §6 (`PriceEntry`, `PriceTable`), `apps/sidecar/src/services/price-source.ts` (temporary seed source from M3-02), `config/pricing.seed.json`

## Scope
- `apps/sidecar/src/infra/sqlite/schema.ts` (+ `price_tables` table) + drizzle migration (`db:generate`; if blocked note it — QA generates; **do not hand-write**), `apps/sidecar/src/ports/price-repository.ts`, `apps/sidecar/src/infra/sqlite/price-repository.ts`, `apps/sidecar/src/services/pricing-service.ts`, `apps/sidecar/src/services/price-source.ts` (switch to the repository), `apps/sidecar/src/container.ts`, tests

## Requirements
1. `price_tables(version pk, effective_from, origin, entries_json)`; first start imports `config/pricing.seed.json` as version `seed-…` if the table is empty.
2. `PricingService.current()` → latest version; `get()` RPC `pricing.get`.
3. `pricing.override({entry})`: validates the entry (non-negative integers, known `modelKey`), creates a new version = current entries with that model replaced, `origin: manual_override`, records which models are manually overridden (stored in the version JSON metadata) so a future auto/manual refresh (M3-04) preserves them until cleared; add internal `clearOverride(modelKey)` (RPC lands with M4 Settings).
4. `stale` flag: `current().effectiveFrom` older than 30 days → exposed via `pricing.get` result? `PriceTable` shape must not change → expose through a new notification? **No** — keep it internal: method `isStale(now)` used later by the UI task (document in Result).
5. Ledger keeps using the version id at write time (already frozen) — add a test that an override after a call does not change the earlier row's cost.

## Tests
- Seed import once; override creates version N+1 with only that model changed; invalid override rejected; precedence metadata; staleness boundary (29 d 23 h / 30 d / 30 d 1 h) with fake clock; integration `TC-M3-010` (override via RPC over stdio → next chat priced with the new rate, earlier ledger row unchanged).
