# M9-01 — Sidecar production bundle: esbuild + Node SEA + native modules from resources

Milestone: M9 · Role: Implementer (ROLES §1.3) · **Deps pre-installed** (`esbuild` ~0.28.2, `postject` 1.0.0-alpha.6 at the root)

## Read first
`AGENTS.md`, **ARCHITECTURE §14.2**, `apps/sidecar/src/main.ts`, `container.ts`, `infra/sqlite/database.ts` (better-sqlite3, migrations folder), `infra/lancedb/vector-store.ts` (lazy LanceDB), `infra/keychain-secret-store.ts` (@napi-rs/keyring), `apps/desktop/src-tauri/src/sidecar/spawn.rs` (how the dev sidecar is spawned today).

## Scope
- `scripts/build/build-sidecar.mjs`, `scripts/build/sea-config.json`, `scripts/build/smoke-sidecar.mjs` (new), root `package.json` scripts only (`build:sidecar`, `smoke:sidecar`), `apps/sidecar/src/infra/native-modules.ts` (new, + test), the three native-module call sites (load through `native-modules.ts`), `apps/sidecar/src/infra/sqlite/database.ts` (migrations folder resolution), `.gitignore` (`dist-sidecar/`).
- **No Tauri config changes** (M9-02 wires `externalBin`).

## Requirements
1. `npm run build:sidecar` → esbuild bundles `apps/sidecar/src/main.ts` (platform node, target node24, minified, external sourcemap) into `dist-sidecar/sidecar.js` in the module format Node SEA requires; native packages (`better-sqlite3`, `@lancedb/lancedb` and its platform package, `@napi-rs/keyring`) are external.
2. Build a Node **Single Executable Application** following the Node 24 documentation (SEA config blob + `postject` into a copy of `node.exe` with the SEA fuse), output `dist-sidecar/itstudio-sidecar-x86_64-pc-windows-msvc.exe`.
3. Copy the required `.node` binaries, the migrations folder, `config/*.json` seeds and the vsix (if built) into `dist-sidecar/resources/`, plus a manifest listing each file with its sha256.
4. `native-modules.ts`: in SEA mode load native modules from `<exe dir>/resources/…` by absolute path; in dev keep the normal imports. At startup verify each native module loads; on failure log a fatal entry naming the missing file and exit with code 2.
5. `npm run smoke:sidecar`: spawn the built exe with a temp `ITSTUDIO_DATA_DIR`, **keep stdin open** (the sidecar exits on stdin EOF), wait for the ready notification, call `system.ping`, measure time-to-ready, send `system.shutdown`; exit 0 on success and print the time-to-ready (PERF-01 target < 1.5 s).

## Acceptance criteria
- [ ] `npm run typecheck && npm run lint && npm test` exit 0; `npm run build:sidecar` and `npm run smoke:sidecar` succeed — QA verifies outside the sandbox; if the sandbox blocks building or running the exe, record it under Open issues. Do not run E2E.
