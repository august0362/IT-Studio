# M13-03 — Gmail send: RFC 5322 composition, threading, Outbox integration

Milestone: M13 · Depends on: M13-02 · Role: Implementer · Size M · **Deps pre-installed**
Requirements: FR-GM-05, FR-OB-03 (Gmail validation)

## Scope
- `apps/sidecar/src/domain/rfc5322.ts` (+ test: compose + address validation), `providers/channel/gmail/gmail-adapter.ts` (`send`), outbox validation hook for Gmail

## Requirements
1. `composeMessage({from, to[], subject, body, inReplyTo?, references?})` → string with CRLF line endings: `From`, `To`, `Subject` (RFC 2047 B-encoded UTF-8 when non-ASCII), `Date` (injected clock), `Message-ID` (`<uuid@itstudio.local>`), `MIME-Version: 1.0`, `Content-Type: text/plain; charset=UTF-8`, `Content-Transfer-Encoding: base64` (body base64, 76-char lines), threading headers when replying. Header injection impossible: CR/LF in any header value → `VALIDATION`.
2. Reply defaults: subject `Re: <original>` (no double "Re:"), `In-Reply-To` = original `Message-ID`, `References` = original references + original id.
3. Send: `messages.send({ raw: base64url(composed), threadId })` → `externalMessageId`.
4. Address validation: `local@domain` pragmatic regex + max 20 recipients + no display-name injection.

## Tests
Golden-file tests for composition (ASCII, Vietnamese subject/body, reply chain), header injection negatives, msw send success/failure classification.
