`AGENTS.md`, ARCHITECTURE §13.1, `apps/sidecar/src/services/activity-recorder.ts` (mapping table), `services/rag/retriever.ts`, `services/command-runner.ts`, `services/vscode-bridge.ts`, `services/image-service.ts`, `apps/desktop/src/features/{workflow,chat,code,knowledge,cost}/**`.

## Scope
- Sidecar: publish **internal** in-process events (no new RPC notifications needed) where the recorder cannot derive activity today, and map them in `activity-recorder.ts` (+ tests):
  - Retriever: query started / completed with hit count, top score, duration (never the query text).
  - Command runner: command started / finished with executable name, exit code, duration, timed-out flag (never full args if they may contain secrets — executable + arg count only).
  - VS Code bridge: action sent / acked (`reveal`, `show_diff`, `transaction`, `notify`) with workspace-relative path.
  - Image service: generation started / completed / failed with provider, count, cost.
  - Embeddings dispatcher: batch embedded with model, chunk count, cost.
- Desktop: deep links select the item — Chat opens the referenced conversation, Code opens the referenced pipeline run, Knowledge highlights the ingest job, Cost filters the ledger by request / run id (each page accepts an optional selection from a tiny shared `navigation-intent` store; no router library).
- Tests: unit per new mapping row; integration `TC-MW-004` (RAG chat + pipeline with a validation command → retriever, command runner, embeddings nodes get events); component tests for each deep link.

## Requirements
- Summaries stay redacted (redaction corpus test extended with command args containing `--token=…` and query text).
- No polling; events only.
