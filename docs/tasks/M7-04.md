# M7-04 — Extension actions: reveal, show diff, transaction decorations, notify

Milestone: M7 · Depends on: M7-01, M7-02 · Role: Implementer (ROLES §1.3) · **Deps pre-installed**

## Goal
When the sidecar writes code, VS Code automatically opens the changed files, can show before/after diffs, decorates changed ranges, and surfaces notifications (ARCH §10.2) — the user never has to touch VS Code.

## Read first
- `AGENTS.md`, `ARCHITECTURE.md` §10.2, `schemas.ts` §11 (`SidecarToExt`: `reveal`, `show_diff`, `transaction`, `notify`, `request_diagnostics`), `apps/vscode-ext/src/{bridge,extension,session}.ts`

## Scope
- `apps/vscode-ext/src/**` only (new `actions.ts`, `diff-provider.ts`, `decorations.ts` + tests)

## Requirements
1. `actions.ts`: handlers registered on the bridge for `reveal` (open file at line, preserve focus false), `show_diff` (virtual documents via a `TextDocumentContentProvider` scheme `itstudio-diff:` holding before/after in memory, `vscode.diff` with the given title), `transaction` (`committed` → if setting `revealChangedFiles` true: open first changed path; decorate all changed paths; `rolled_back` → clear decorations + warning message), `notify` (info/warning/error message), `request_diagnostics` (reply with diagnostics from `vscode.languages.getDiagnostics()` for workspace files, mapped to `Diagnostic` with workspace-relative paths). Every handler acks with `{type:'ack', ref}`.
2. Path safety: every `path` from the sidecar is resolved against the workspace root; reject absolute paths, `..`, or paths escaping the root (log + ack without action).
3. Memory bound for diff provider: keep at most 20 diff entries (LRU).
4. Keep `vscode`-dependent code thin; put logic in pure functions tested without `vscode` (inject an `EditorPort` interface with fake implementation in tests).

## Tests
- Pure tests with fake `EditorPort`: each message type, ack sent, path rejection cases, LRU eviction, diagnostics mapping (severity, 0→1-based lines, relative paths).
