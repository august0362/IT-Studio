# M6-05 — PipelineOrchestrator: PM → Coder → Reviewer (≤ 1 fix) → Worker write → validation → complete / rollback

Milestone: M6 · Depends on: M6-01…M6-04, M6-06, M2-07 · Role: Implementer (ROLES §1.3) · **Deps pre-installed**

## Goal
`pipeline.start(prompt)` runs the full runtime pipeline of ARCH §8.1 safely: specs and code come from the role models, nothing touches disk until the reviewer approves, every write is journaled, validation failure rolls back byte-identically, and the user gets a `FailureReport` with next steps (D5, D11, D16).

## Requirements
1. Pure stage machine (State pattern, explicit transition table, illegal transitions rejected): SPECIFYING → CODING → REVIEWING → (approved) WRITING | (rejected, fixAttempts 0) FIXING → RE_REVIEWING → (approved) WRITING | (rejected) FAILED; WRITING → VALIDATING | ROLLED_BACK; VALIDATING → COMPLETED | ROLLED_BACK; cancel → CANCELLED (before WRITING) or ROLLED_BACK (during WRITING/VALIDATING).
2. `pipeline.start({projectId, prompt})` returns the `PipelineRun` immediately (stage SPECIFYING) and runs asynchronously; **one run per project** at a time (second start while active → queued in order; `pipeline.list` shows both); different projects run in parallel.
3. Role calls via `RoleCaller` with the project's `RoleAssignment`; PM gets prompt + file tree + conventions summary (first 2 000 chars of the project's `CONVENTIONS.md` if present); Coder gets `TaskSpec` + contents/hashes of `allowedPaths`; Reviewer gets spec + coder output + unified diffs (generate with a small pure diff helper — reuse `domain/unified-diff.ts` if it can render).
4. WRITING: `WriteTransaction.prepare` (allowedPaths from the spec, re-validated by path guard) → `commit`; any error → rollback + FAILED/ROLLED_BACK with report. VALIDATING: run `settings.pipeline.validationCommands` via `CommandRunner` sequentially; first failing command → rollback → ROLLED_BACK; all pass → `markValidated` → COMPLETED.
5. Publish `pipeline.event` for every stage, `artifact` events for spec/code/review, `command_output` chunks, `finished`; on failure publish `pipeline.failureReport` from `FailureReportBuilder`. Persist the run (stage + artifacts + cost total from ledger rows with this `pipelineRunId`).
6. `pipeline.get`, `pipeline.list({projectId, limit})`, `pipeline.cancel({runId})`.
7. Budget Hard Stop between calls stops the run at the next boundary (before WRITING → FAILED; during → rollback).

## Tests
- Pure machine: every legal and illegal transition (table-driven), cancel in each stage.
- Orchestrator (fake RoleCaller/CommandRunner, memory FS): happy path → COMPLETED and files written; reviewer reject → fix → approve; reject twice → FAILED with nothing written; validation fails → ROLLED_BACK byte-identical; coder path outside allowedPaths → rejected before write; cancel during VALIDATING → rollback; per-project queue; parallel projects.
- Integration `TC-M6-001` (scripted LLM fixture returning valid JSON spec/code/verdict for `sample-project`, validation command = a tiny `node` script that passes) → COMPLETED and file on disk; `TC-M6-002` failing validation script → ROLLED_BACK with tree hash identical to before and a `pipeline.failureReport`.
