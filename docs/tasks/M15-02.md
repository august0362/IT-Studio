# M15-02 — SSH key vault: import, AES-256-GCM at rest, keychain data keys, zeroing

Milestone: M15 · Depends on: M15-00 · Role: Implementer · Size M · **Deps pre-installed** (`ssh2`)

## Scope
- `apps/sidecar/src/domain/key-envelope.ts` (+ test: pure format encode/decode), `apps/sidecar/src/services/key-vault.ts` (+ test), `ports/key-vault.ts`, `services/server-registry.ts` (`add`, `replaceKey` using the vault), `src/types/schemas.ts` RPC `server.add`, `server.replaceKey` + validators, `container.ts`, `domain/remediation.ts` (`KEY_INVALID`)

## Contracts
```ts
interface IKeyVault {
  importKey(serverId: ServerId, keyPath: string, passphrase?: string): Promise<Result<{ keyType: string; hasPassphrase: boolean }>>;
  withPrivateKey<T>(serverId: ServerId, fn: (key: Buffer, passphrase: string | undefined) => Promise<T>): Promise<Result<T>>; // zeroes in finally
  delete(serverId: ServerId): Promise<Result<void>>;
}
```

## Requirements
1. Import: read file (≤ 16 KB, else `KEY_INVALID`), parse with `ssh2` `utils.parseKey(data, passphrase)`; reject public keys, RSA < 2048, unsupported types, wrong/missing passphrase for encrypted keys (distinct messages).
2. Envelope `v1:` + base64(iv 12 B ‖ tag 16 B ‖ ciphertext), AES-256-GCM, AAD = serverId; data key 32 random bytes in keychain `itstudio-ssh/<serverId>` (base64); passphrase in `itstudio-ssh-pass/<serverId>`; file `<dataDir>/ssh/<serverId>.key.enc` written atomically (tmp + rename), directory created with restrictive ACL where possible (document Windows behaviour).
3. `withPrivateKey`: decrypt to a Buffer, call `fn`, zero the buffer and the data key buffer in `finally`; tamper / wrong AAD → `KEY_INVALID` "key file damaged — replace key".
4. Never log key material, paths are fine. `server.add` = validate input (M15-01) → insert row → import key → on import failure delete the row (no half-created servers).

## Tests
Round trip with generated ed25519 / ECDSA / RSA-2048 / RSA-1024 (✗) / encrypted keys (right/wrong passphrase); tamper bit-flip; AAD mismatch; zeroing verified with a spy on `Buffer.prototype.fill` or by holding a reference; keychain fake. Fixtures generated at test time with `ssh2` utils or node `crypto.generateKeyPairSync` — no private keys committed (secret scanner!).
