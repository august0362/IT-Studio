# M9-05 — Version bump script + release CHANGELOG automation

Milestone: M9 · Role: Implementer (ROLES §1.3) · **Deps pre-installed** · Effort: small

## Scope
`scripts/release/bump-version.mjs` (+ test with fixture manifests under `scripts/release/__fixtures__/`), root `package.json` scripts only (`release:bump`), `docs/RUNNING.md` (§6 release checklist lines only).

## Requirements
1. `npm run release:bump -- <major|minor|patch|x.y.z>` updates the version consistently in **5** places: root `package.json`, `apps/desktop/package.json`, `apps/sidecar/package.json`, `apps/vscode-ext/package.json`, `apps/desktop/src-tauri/tauri.conf.json` (+ `Cargo.toml` `[package] version`); refuses if they disagree before the bump (prints the table) unless `--force`.
2. CHANGELOG: move the `## [Unreleased]` section to `## [x.y.z] — YYYY-MM-DD` and add a fresh empty `## [Unreleased]` with the standard subsections; refuse if Unreleased is empty.
3. `--dry-run` prints the diff without writing. Pure functions for parsing / bumping are unit-tested (semver bump table, prerelease rejected, malformed manifests).
4. RUNNING.md §6: add the release checklist (`release:bump`, `audit:prod`, `build:app`, install smoke, tag).

## Acceptance criteria
- [ ] `npm run typecheck && npm run lint && npm test` exit 0. Do not run E2E. Do not actually bump the repo version.
