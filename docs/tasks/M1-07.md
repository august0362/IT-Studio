# M1-07 — UI status bar + Settings → API Keys page

Milestone: M1 · Depends on: M1-04, M1-06 · Role: Implementer (ROLES §1.3) · **Deps pre-installed**

## Goal
The user can see whether the sidecar is connected and enter/verify/delete provider API keys from the UI; keys are write-only.

## Read first
- `AGENTS.md`, `CONVENTIONS.md` §4, `ARCHITECTURE.md` §11, `schemas.ts` §3 (`SecretStatus`), `docs/tasks/M1-04.md` (hooks), `docs/design/THEMES.md` §5.2 (use semantic token classes only, no raw colors — tokens arrive in M4-01b; until then use Tailwind neutral classes sparingly and keep them centralised in one `ui/` component file)

## Scope — files you may create/modify
- `apps/desktop/src/App.tsx`, `apps/desktop/src/components/**`, `apps/desktop/src/features/settings/api-keys/**`, tests next to files

## Requirements
1. Layout shell (minimal, replaced in M4-01): left nav with "Settings" only for now; bottom status bar.
2. Status bar: sidecar state from `useSidecarStatus()` — `Connecting…` / `Ready vX.Y.Z` (from `system.ping`) / `Restarting (n)` / fatal banner with log folder path.
3. API Keys page: one row per `ProviderId` with display name, status chip (Not set / Set ••••abcd / Verified at time / Invalid), password input (never pre-filled), Save, Verify, Delete (confirm dialog). After save, input clears. Errors render `AppError.message` + `remediation` list.
4. Accessibility: labelled inputs, buttons reachable by keyboard, status chips have text not just color.

## Tests
- Status bar states via fake transport.
- Save clears the input and never renders the typed key back; Verify success/failure states; Delete confirm flow.

## Acceptance criteria
- [ ] `npm run typecheck && npm run lint && npm test` exit 0
- [ ] No API key value is ever placed in component state after the save call resolves
