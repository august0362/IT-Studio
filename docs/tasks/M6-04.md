# M6-04 — Runtime role prompts + JSON output validation with one re-ask

Milestone: M6 · Depends on: M1-01, M2-07 · Role: Implementer (ROLES §1.3) · **Deps pre-installed**

## Goal
The PM, Coder and Reviewer roles get their exact prompts (ROLES §2.1–§2.3 + common rules), their JSON outputs are validated against `TaskSpec` / `CoderOutput` / `ReviewVerdict`, and an invalid answer is re-asked once with the validation error (ARCH §8.1).

## Read first
- `AGENTS.md`, `ROLES.md` §2 (common rules), §2.1–§2.3 (verbatim prompts), `ARCHITECTURE.md` §8.1, `schemas.ts` §8, `apps/sidecar/src/validation/pipeline.ts` (`taskSpecSchema`, `coderOutputSchema`, `reviewVerdictSchema`, `toJsonSchema`), `apps/sidecar/src/services/llm-router.ts`

## Scope
- `apps/sidecar/src/prompts/{common,pm,coder,reviewer}.ts` (+ tests), `apps/sidecar/src/services/role-caller.ts` (+ test), `apps/sidecar/src/domain/template.ts` (+ test — tiny `{{var}}` / `{{#flag}}…{{/flag}}` renderer)

## Requirements
1. Prompts are verbatim from ROLES §2.1–§2.3 with the common rules appended; placeholders filled by `domain/template.ts` (no eval; unknown placeholder → error; values inserted as-is inside `<context>` blocks; `{{#fixRound}}` sections toggled by boolean).
2. Any user/repo/RAG/model-produced text inserted into a prompt is wrapped as `<context name="...">…</context>` and has any literal `</context>` sequences neutralised (e.g. `</context>` → `<\/context>`) to prevent block escape (prompt-injection containment).
3. `RoleCaller.call(role, inputs, { projectId, pipelineRunId, ladder })`: builds the prompt, calls `LlmRouter.dispatch` with `responseFormat: 'json'`, `purpose: pipeline_pm|pipeline_coder|pipeline_reviewer`, `ladderOverride` = role ladder; extracts the first top-level JSON object from the reply (tolerate leading/trailing prose and ```json fences), validates with the role schema; on failure re-asks **once** with the zod issues summarised (≤ 2 000 chars) appended; second failure → `Result` error `VALIDATION` with remediation.
4. Reviewer rule enforced in code: if any finding is `blocker`/`major`, force `approved = false` (log when overriding the model).

## Tests
- Template renderer: variables, sections, unknown placeholder, no injection via values.
- `</context>` neutralisation.
- RoleCaller with FakeLlmProvider: valid JSON first try; fenced JSON; invalid then valid (re-ask contains issues); invalid twice → VALIDATION; reviewer approved-with-blocker → forced false; purposes/ladders passed to the router.
