# UX-05 — Theme and visual design overhaul (Codex owns the design)

Milestone: v1 owner acceptance feedback (2026-10-16) · Role: Implementer **and designer** · Size L · Model: gpt-6.1-sol, effort high · **Broad scope inside `apps/desktop/src/**`, `config/themes.json`, `scripts/design/**`, `apps/desktop/index.html` (theme boot script), `docs/design/**`: do not stop for edits needed to meet a requirement — list them in Result**

## Owner request

"The theme part is too plain. Give the theme work to Codex. Don't hard-code a particular style or effects for it — let Codex decide and build it."

You have **creative freedom**. Palette, typography, spacing scale, radii, elevation, surfaces (glass, gradients, glow or none), iconography and motion are your decisions. Aim for a cohesive, modern, professional desktop look that feels designed, not default. Explain the choices in `docs/design/theme-system.md`.

## Read first

`docs/design/THEMES.md`, `docs/design/DARK-GLOW.md`, `config/themes.json` + `scripts/design/derive-themes.mjs`, `apps/desktop/src/theme/**`, `apps/desktop/src/components/ui/**`, `apps/desktop/index.html` (pre-paint theme script), `apps/desktop/src/index.css`, the Settings → Appearance section.

## Hard constraints (the only non-negotiables)

1. **Accessibility:** WCAG 2.1 AA contrast for text/background and UI-component pairs in every theme and mode.
   - Add an automated contrast test that iterates every theme × light/dark × token pair and fails below threshold.
   - Visible focus rings everywhere.
   - `prefers-reduced-motion` disables non-essential motion.
2. **Compatibility:**
   - Existing saved selections keep working: theme ids in `itstudio.theme` storage and settings either still exist or are migrated to the closest new theme.
   - Light/dark/system modes stay.
   - The pre-paint boot script in `index.html` must keep avoiding a flash of the wrong theme. Regenerate it from the source if `themes.json` changes.
3. **Consistency:**
   - Components use theme tokens, not hard-coded colours. Grep for stray hex/rgb in `apps/desktop/src` and convert them, except Pipeline Studio / process viewer, which stay pure black by design (D35/D40); you may refine their accents to match the new system.
4. **Vietnamese text** renders correctly (diacritics) in the chosen fonts.
   - You may add **at most two** `@fontsource*` font packages, with a justification in Result.
   - Fonts are bundled offline, never loaded from a CDN at runtime.
5. **Performance:**
   - No layout jank. Prefer GPU-friendly effects (opacity/transform).
   - Large lists (chat, processes, tables) must not slow down because of heavy filters or shadows.
6. **No behaviour changes** outside styling and the Appearance section. Keep `data-testid`s/roles/labels so existing tests keep passing; update only snapshot/class assertions that are purely visual.

## What to deliver

- A refined **design-token system**: colour roles, surfaces/elevation, typography scale, spacing, radii, motion durations/easings, z-index. Document the token names.
- **Themes:** curate the set. Quality over quantity. You may reduce, rename or replace themes as long as old ids migrate. Each theme has a deliberate light and dark variant.
- **Shared UI primitives** restyled: buttons, inputs, selects, checkboxes/switches, tabs, cards, tables, dialogs, toasts, badges/chips, tooltips, scrollbars, empty states.
- The shell (sidebar, project tabs, status bar), chat bubbles/code blocks/markdown, and settings pages must use the primitives so the app feels like one product.
- **Settings → Appearance** redesigned:
  - A gallery of live theme preview cards: mini app mock in each theme, current-mode preview, select on click.
  - Light/dark/system mode.
  - At least: accent colour override (from theme-safe options), density (comfortable/compact), UI font size scale, motion (full/reduced/system).
  - Settings persist through the existing settings/theme storage, additive fields only.
- `docs/design/theme-system.md`: principles, token reference, how to add a theme, screenshots list for QA.
