# M7-02 — Sidecar `VSCodeBridge`: loopback WebSocket server, token auth, heartbeat

Milestone: M7 · Depends on: M7-01 · Role: Implementer (ROLES §1.3) · **Deps pre-installed** (`ws` + `@types/ws` — Architect installs before launch)

## Goal
The sidecar side of the VS Code connection (ARCH §10.1): a loopback-only WebSocket server that authenticates the companion extension, keeps a heartbeat, writes the session file, and publishes `vscode.status`.

## Scope
- `apps/sidecar/src/services/vscode-bridge.ts` (+ test), `apps/sidecar/src/services/vscode-session-file.ts` (+ test), `apps/sidecar/src/validation/vscode.ts` (reuse existing schemas only), `apps/sidecar/src/container.ts` (wire, start on project activation), `apps/sidecar/test/integration/vscode-bridge.test.ts`

## Requirements
1. `ws` server bound to `127.0.0.1` port `0`; 32-byte random token (hex, 64 chars) per sidecar session (crypto.randomBytes).
2. Reject upgrade requests that carry an `Origin` header (browser pages) with 403; reject non-loopback remote addresses.
3. First frame must be a valid `ExtHello` within 5 s: protocolVersion 1, token compared with `crypto.timingSafeEqual`, `workspaceRoot` equal (realpath, case-insensitive on Windows) to the active project root → reply `welcome{sessionId}`; else close with code 4401/4400.
4. Heartbeat: send `ping` every 15 s; close + `vscode.status{connected:false}` after 2 missed `pong`s (injected clock/timers).
5. Session file `.itstudio/session.json` `{port, token, protocolVersion:1}` written atomically (tmp+rename) on project activation; ensure `.itstudio/` is listed in the project's `.gitignore` (append once). Token rotates on every sidecar start.
6. Inbound `diagnostics` → publish `vscode.diagnostics{projectId, diagnostics}`; `file_saved_by_user` → internal event for M6 (emit on internal bus only). Invalid frames ignored and logged (never echo content).
7. `send(message: SidecarToExt)` API with incrementing `ref` for later tasks (M7-04).
