# M7-03 — VS Code launcher + extension installer + vsix build

Milestone: M7 · Depends on: M7-01, M7-02 · Role: Implementer (ROLES §1.3) · **Deps pre-installed** (`@vscode/vsce` ~4.0.0 added to `apps/vscode-ext` devDependencies by the Architect)

## Goal
When a project becomes active (and `settings.vscode.autoLaunch` is on), IT Studio makes sure its companion extension is installed in VS Code and opens the project folder in VS Code — without a shell — so the user never has to set anything up (D3, ARCH §10.1 steps 3–4).

## Requirements
1. **Resolve VS Code CLI** (`code-cli.ts` pure + launcher I/O): `settings.vscode.codeExecutable` if set, else search `PATH` entries for `code.cmd` / `code`, then the default install dirs (`%LOCALAPPDATA%\Programs\Microsoft VS Code\bin`, `%ProgramFiles%\Microsoft VS Code\bin`). On Windows `code.cmd` **must not be spawned** (Node refuses `.cmd` with `shell:false`): parse it for the line `"%~dp0..\Code.exe" "%~dp0..\<dir>\resources\app\out\cli.js"` and run `Code.exe` with first arg the resolved `cli.js` and env `ELECTRON_RUN_AS_NODE=1` (fallback: glob `..\*\resources\app\out\cli.js`, newest). On macOS/Linux spawn the `code` script directly. Not found → `VSCodeStatus{installed:false,…}` + one warning notification text; never fail project activation.
2. All spawns via the existing process-runner port: `shell:false`, env allow-list (+ `ELECTRON_RUN_AS_NODE`), 30 s timeout, output capped.
3. **Installer:** `<cli> --list-extensions --show-versions` → if `itstudio.itstudio-vscode@<bundledVersion>` missing or different → `<cli> --install-extension <vsixPath> --force`. `vsixPath` = env `ITSTUDIO_VSIX_PATH` or `<repo>/apps/vscode-ext/dist/itstudio-vscode.vsix` in dev (bundled-resource path is M9-02); missing vsix → status `extensionInstalled:false` + warning, still launch VS Code. Check once per sidecar session (cache the result).
4. **Launch:** if `autoLaunch` → `<cli> <workspaceRoot>` detached (do not wait for VS Code to exit; do not kill it on sidecar shutdown). Re-activating the same project within one session does not relaunch.
5. `vscode.status` published after each step (installed / extensionInstalled / workspaceRoot / extensionVersion); `connected` keeps coming from the bridge.
6. `ITSTUDIO_E2E=1`: launcher is a no-op recorder (never starts real VS Code).
7. **vsix build:** `npm run package -w itstudio-vscode` = build + `vsce package --no-dependencies --allow-missing-repository --skip-license -o dist/itstudio-vscode.vsix`; `.vscodeignore` keeps only `dist/extension.js` and `package.json` (+ README if present).

## Tests
- `code-cli.ts`: parse real-format `code.cmd` (with commit-hash dir), malformed file, path with spaces, non-Windows passthrough.
- Launcher (fake FS + fake process runner): resolution order (setting > PATH > default dirs), not found → status + no throw, install when missing / outdated / skip when same version, missing vsix, launch args and env (`ELECTRON_RUN_AS_NODE=1`, `shell:false`), detached + no relaunch for same project, autoLaunch off → no launch, E2E no-op.
