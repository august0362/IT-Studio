## Requirements
1. `rag.query(RetrievalQuery)`: validate `topK` 1–20, `minScore` in [0,1], non-empty query (≤ 2 000 chars). Embed the query with the **same model** as the project's index; if the index model/dimensions differ from the configured embedding model → `VALIDATION` "Knowledge index uses another embedding model — re-index required". Empty index → `[]`.
2. Vector search `topK × 2` candidates → drop score `< minScore` → MMR re-rank to `topK` with λ = 0.7 (`mmr.ts`: pure, deterministic tie-break by chunkId; similarity between candidates = cosine of their vectors). `tagFilter` restricts to documents having **all** given tags. Hits carry `documentTitle` and `sectionPath`.
3. Chat with `ragEnabled = true`: before each user turn run retrieval with `settings.rag.defaultTopK` / `minScore`; render the system prompt with ROLES §2.6 verbatim via `domain/template.ts`, `numberedHits` = `[n] <title> › <sectionPath joined by " › ">\n<text>` blocks, each hit text **neutralised** (case-insensitive `</context>`). No hits → render without the rag section. Retrieval/embedding failure → log warning and answer without RAG (never fail the chat for it), except Budget Hard Stop which fails the turn as usual.
4. The assistant `ChatMessage` gets one `citation` part per hit actually cited as `[n]` in the reply text (parse `[n]` markers; ignore numbers out of range; keep first-occurrence order; de-duplicate).
5. `chat.setRagEnabled` persists the flag and returns the updated `Conversation`; unknown id → `NOT_FOUND`.
6. Tool `search_knowledge` (`SearchKnowledgeArgs`): executor function in `retriever.ts` returning hits (topK default `settings.rag.defaultTopK`, capped at 20) for use by agent roles later; not wired into chat tool-calling in this task.
7. Embedding of the query is metered (ledger `purpose = embedding`, project of the query).

## Tests
- MMR: λ = 1 → pure relevance order; λ = 0 → max diversity; duplicates pushed down; ties deterministic; topK > candidates.
- Retriever (memory vector store + fake dispatcher): minScore boundary (equal kept, below dropped), tagFilter all-of, model mismatch → VALIDATION, empty index.
- Chat service: prompt contains numbered blocks with neutralised `</CONTEXT>`; no hits → no rag section; retrieval failure → normal answer + warning; citations parsed (`[2]`, `[2][1]`, `[9]` out of range ignored).
- Integration `TC-M5-010`: ingest fixtures (fake embeddings) → `rag.query` returns hits ordered, all ≥ minScore; `TC-M5-011`: `chat.setRagEnabled` true → scripted reply containing `[1]` → assistant message has a `citation` part for hit 1.
