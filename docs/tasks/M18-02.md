# M18-02 — Remote read, safe write (hash check, backup, atomic rename), undo

Milestone: M18 · Depends on: M18-01 · Role: Implementer · Size L · **Deps pre-installed**
Requirements: FR-FS-02, FR-FS-03, FR-FS-04, NFR-V3-08 · D27 · DD-V3-08 · SRS v3 §7.3

## Scope
`apps/sidecar/src/domain/text-file.ts` (+ test: UTF-8/binary detection, EOL + trailing newline detection and re-application), `services/sftp/remote-safe-write.ts` (+ test), `services/sftp/sftp-service.ts` (`read`, `write`, `undo`), `src/types/schemas.ts` RPC `sftp.read|write|undo` + validators, integration `apps/sidecar/test/integration/sftp-write.test.ts`.

## Requirements
1. `read`: stat first (> 5 MB → `REMOTE_FILE_TOO_LARGE`); read bytes; NUL byte or invalid UTF-8 → `REMOTE_FILE_BINARY`; return content (with `\n` line endings normalised for the editor), `eol` (`crlf` if the majority of line breaks are CRLF), `trailingNewline`, `sha256` of the **raw bytes**, size, mtime.
2. `write(req)`: rebuild bytes from content + eol + trailingNewline; re-read current raw bytes → hash ≠ `baseSha256` → `CONFLICT` (`details.currentSha256`); if `backup` (default true) copy current file to `<file>.itstudio-bak-<YYYYMMDDHHmmss>` (UTC, collision → `-2`), preserve mode; write `<file>.itstudio-tmp` (same dir, mode of original), fsync where supported, then rename over the target (POSIX: SFTP `posix-rename@openssh.com` when available, else remove + rename; Windows host: remove + rename) → stat + hash → result. Any failure after the backup: remove tmp, ensure target equals either old content or new content (verify hash; if neither, restore from backup) and return the error with the backup path in remediation.
3. Keep the newest 5 backups per file; delete older ones only after a successful write.
4. `undo(path)`: newest backup → safe-write it over the target (with a fresh backup of the current content) → result.
5. No content in logs or activity summaries.

## Tests
Text detection table (UTF-8 BOM, CRLF/LF/mixed, no trailing newline, binary, Latin-1 → binary); write paths: success, conflict, backup naming collision, retention 5, fault injection at each step (connection drop during tmp write, rename failure) → target intact + backup present; undo twice. Integration `TC-M18-010` edit `.env` round trip; `TC-M18-011` concurrent external change → `CONFLICT`.
