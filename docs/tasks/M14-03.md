# M14-03 — Facebook send: 24 h window, rate-limit backoff

Milestone: M14 · Depends on: M14-02 · Role: Implementer · Size M · **Deps pre-installed**
Requirements: FR-FB-03, FR-FB-04, FR-FB-05, FR-OB-06

## Scope
- `apps/sidecar/src/domain/messaging-window.ts` (+ test), `domain/meta-rate-limit.ts` (+ test: header parsing), `providers/channel/facebook/facebook-adapter.ts` (`send`), outbox validation hook (body ≤ 2 000 chars)

## Requirements
1. `canSend(now, sendBefore)` ⇔ `now < sendBefore` (strict). Outbox approve already checks expiry; the adapter re-checks right before sending (race-safe).
2. Send: `POST /{page-id}/messages` JSON `{ recipient: { id: <customer id> }, messaging_type: "RESPONSE", message: { text } }`; result `message_id`.
3. Rate limit: parse `x-business-use-case-usage` (per business id → array of `{call_count,total_cputime,total_time,estimated_time_to_regain_access}`) and `x-app-usage`; any metric ≥ 90 or HTTP 429 / codes 4, 17, 32, 613, 80006 → `CHANNEL_RATE_LIMITED` with `details.retryAt` (= now + `estimated_time_to_regain_access` minutes, else 60 s); the account is marked limited until then (sync and send return the same error without calling Graph).
4. Error 10 with subcode 2018278 (outside window) → `MESSAGING_WINDOW_EXPIRED`.

## Tests
Window BVA: `sendBefore` − 1 s / = / + 1 s; header parser corpus (missing, malformed JSON, multiple businesses, 89/90/91); send success/failure mapping; limited-account short-circuit.
