# M7-05 — Diagnostics streaming + user-save conflict signal

Milestone: M7 · Depends on: M7-02, M7-04 · Role: Implementer (ROLES §1.3) · **Deps pre-installed**

## Goal
VS Code pushes its Problems-panel diagnostics to the app (debounced), and tells the sidecar when the user saves a file, so a running pipeline can detect conflicts (ARCH §10.2).

## Read first
- `AGENTS.md`, `ARCHITECTURE.md` §10.2, `schemas.ts` §11 (`ExtToSidecar.diagnostics`, `file_saved_by_user`), `apps/vscode-ext/src/{bridge,actions,extension}.ts`, `apps/sidecar/src/services/vscode-bridge.ts`

## Scope
- `apps/vscode-ext/src/**` (new `diagnostics-push.ts`, `save-watcher.ts` + tests), `apps/sidecar/src/services/vscode-bridge.ts` (+ test) — only the inbound handling of these two messages. **No container changes.**

## Requirements
1. Extension: subscribe to `vscode.languages.onDidChangeDiagnostics`; debounce 500 ms; send full workspace snapshot (reuse M7-04 mapping), capped at 500 diagnostics (errors first, then warnings), only while connected.
2. Extension: `workspace.onDidSaveTextDocument` → for files inside the workspace send `{type:'file_saved_by_user', path, hash}` (sha256 of the saved text); ignore saves of files under `.itstudio/`, `node_modules/`, `.git/`; ignore saves triggered within 2 s after a sidecar `transaction{committed}` for the same path (those are our own writes).
3. Sidecar bridge: validate inbound messages; publish `vscode.diagnostics{projectId, diagnostics}`; emit internal `fileSavedByUser{projectId, path, hash}` event (consumed by the orchestrator in a later integration step).
4. Pure logic separated from `vscode` APIs and tested with fakes.

## Tests
- Debounce (fake timers), cap + ordering, disconnected → nothing sent, save filtering rules incl. 2 s own-write window, sidecar validation and publication.

## Acceptance criteria
- [ ] `npm run typecheck && npm run lint && npm test` exit 0; `npm run build -w itstudio-vscode` succeeds (QA verifies outside sandbox)
