# M16-04 — MetricsCollector scheduler: watch / unwatch, background mode, ring buffer

Milestone: M16 · Depends on: M16-01 (M16-02/03 plug in when ready) · Role: Implementer · Size L · **Deps pre-installed**

## Scope
- `apps/sidecar/src/services/metrics/metrics-collector.ts` (+ test), `services/metrics/ring-buffer.ts` (+ test), collector registry by `ServerOs`, `src/types/schemas.ts` RPC `server.watch`, `server.unwatch`, `server.history` + notification `server.metrics`, validators, `container.ts`
- integration `apps/sidecar/test/integration/metrics.test.ts` (fake SSH server with scripted Linux output)

## Requirements
1. Watch registry: `viewId → Set<ServerId>`; polled set = union of watched (background off) or all servers (background on). Settings change (`settings.update` of `monitoring`) re-evaluates immediately.
2. Per server: acquire `metrics` consumer while polled, release when not; timer per server at `pollIntervalSeconds` (3–60); single-flight; > 10 s → `late` flag on the sample; 2 consecutive failures → status `offline` (manager state) and `server.status`.
3. Unknown OS → no polling, status note "OS unknown — set it in Edit".
4. Ring buffer 10 min per server (capacity = 600 / interval, recomputed on interval change, keeping newest).
5. `server.metrics` notification per sample; `server.history(serverId)` returns the buffer.
6. App UI disconnect / project switch do not matter (servers global); `system.shutdown` stops all timers.

## Tests
Fake timers: watch/unwatch ref counting across two views; background on/off switch; interval change; single-flight with slow exec; late flag; offline after 2 failures; no exec when nothing polled (NFR-V3-01 counter on fake server). Integration `TC-M16-010` watch → samples arrive every interval; `TC-M16-011` unwatch + background off → 0 execs over 30 s.
