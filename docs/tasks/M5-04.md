# M5-04 — LanceDB vector store (`IVectorStore`)

Milestone: M5 · Depends on: M5-02 · Role: Implementer (ROLES §1.3) · **Deps pre-installed** (`@lancedb/lancedb@^0.39`, `apache-arrow`)

## Goal
A per-project embedded vector store for RAG chunks (ARCH §7.1–§7.2, D4) behind a port, so the RAG service and later Agent Memory (M11) can share it.

## Read first
- `AGENTS.md`, `ARCHITECTURE.md` §7, §12.2 (`vectors/` dir), `schemas.ts` §7 (`Chunk`, `RetrievalHit`), `CONVENTIONS.md` §7 (no string-built filters)

## Scope
- `apps/sidecar/src/ports/vector-store.ts`, `apps/sidecar/src/infra/lancedb/vector-store.ts` (+ test), `apps/sidecar/src/infra/memory-vector-store.ts` (+ shared contract test `apps/sidecar/src/infra/__contract__/vector-store-contract.ts`)

## Requirements
1. Port: `upsertChunks(table, rows: { chunkId, documentId, projectId, ordinal, text, sectionPath, vector: Float32Array | number[] }[])`, `deleteByDocument(table, documentId)`, `search(table, vector, { topK, minScore, documentIds?, tagFilter? }) → { chunkId, documentId, text, sectionPath, score }[]` (score = cosine similarity in [0,1]), `dropTable(table)`, `count(table)`; all return `Result`.
2. LanceDB impl: database at `<dataDir>/vectors`; table name `chunks_<projectId>` (validated `[A-Za-z0-9_-]`); cosine distance; `score = 1 - distance` clamped; dimension fixed per table (mismatch → `VALIDATION` "re-index required", ARCH §7.3).
3. Filters: build with LanceDB's typed API or escape every value; ids must match the UUID/opaque-id patterns before use — never interpolate raw strings (SQL-injection rule).
4. Memory impl with identical semantics (brute-force cosine) for unit tests; both pass the shared contract suite.

## Tests
- Contract suite against both impls: upsert/search ordering, minScore cut, topK, delete by document, idempotent upsert (same chunkId replaces), dimension mismatch, empty table search, filter by documentIds, malicious id strings rejected.
- LanceDB impl runs against a temp directory (real native module).
