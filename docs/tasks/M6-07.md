# M6-07 — Code tab: run a pipeline and watch it

Milestone: M6 · Depends on: M6-05, M6-08, M4-01 · Role: Implementer (ROLES §1.3) · **Deps pre-installed** (`@monaco-editor/react` ~4.7, `monaco-editor` ~0.57)

## Goal
In the Code tab the user types what to build, starts the PM → Coder → Reviewer → Worker pipeline for the active project, and watches every stage live: spec, code diff, review verdict, validation output, final result or failure report with next steps (ARCH §8, D5, D11, D16).

## Requirements
1. **Monaco offline:** `monaco-setup.ts` configures `@monaco-editor/react`'s `loader.config({ monaco })` with the locally bundled `monaco-editor` (no CDN — Tauri CSP and offline use) and registers Monaco themes from the active theme tokens (THEMES.md bridge); diff editor read-only.
2. **Prompt box:** multiline prompt (≤ 8 000 chars, counter), Run → `pipeline.start({projectId, prompt})`; disabled on "All projects". A queued run (another run active for the project) shows "Queued".
3. **Reducer** (`pipeline-store.ts`, pure, 100 % branches): applies `pipeline.event` (`stage`, `artifact`, `command_output`, `finished`) and `pipeline.failureReport` per `runId`; ignores unknown runs and events after `finished`; command output capped at 2 000 lines per command (drop oldest, show "… truncated").
4. **Timeline:** stages SPECIFYING → CODING → REVIEWING → (FIXING → RE_REVIEWING) → WRITING → VALIDATING → final, with current / done / failed / skipped states (text + icon, not colour alone) and elapsed time.
5. **Artifacts:** on `artifact` events fetch `pipeline.get` and render: spec (`TaskSpec` fields: goal, allowed paths, acceptance criteria), code as per-file Monaco diff (before = previous content provided in the artifact if present, else empty), review verdict with findings (severity badge, path:line); any free text from models goes through `SafeMarkdown`.
6. **Validation output:** live `command_output` per command with stdout / stderr distinguished; auto-scroll unless the user scrolled up.
7. **Cancel:** visible while not finished → `pipeline.cancel`; confirm with the in-app `ConfirmDialog` when the run is in WRITING / VALIDATING ("changes will be rolled back").
8. **Failure report:** `FailureReportPanel` shows stage, error (`ErrorPanel`), rolled back yes/no and the numbered next steps.
9. **Cost:** run cost via `<Money>` from `PipelineRun.cost`, refreshed on each event.
10. **History:** `pipeline.list({projectId, limit: 20})`, newest first; selecting a run loads it read-only.
