# M6-08 — Pipeline cost attribution (follow-up from M6-05 QA)

Milestone: M6 · Depends on: M6-05, M3-02 · Role: Implementer (ROLES §1.3) · **Deps pre-installed**

## Problem
`PipelineRun` cost is always 0. `RoleCaller` knows the `pipelineRunId` but only logs it; `LlmRequest` has no such field, so `RouterCompleted` and the ledger row lose the attribution, and the container wires the orchestrator with `money: () => 0`. ARCH §8.1 / M6-05 req. 5 require the run cost = sum of the ledger rows with this `pipelineRunId`.

## Read first
- `AGENTS.md`, `schemas.ts` §3 (`LlmRequest`), §6 (`LedgerEntry.pipelineRunId`), §8 (`PipelineRun`), `apps/sidecar/src/services/{role-caller,llm-router,ledger-service,pipeline-orchestrator}.ts`, `infra/sqlite/ledger-repository.ts`, `ports/ledger-repository.ts`, `container.ts` (router `completed` → ledger wiring, orchestrator `money`)

## Scope
- `src/types/schemas.ts` — **additive only**: in `LlmRequest` add `readonly pipelineRunId?: PipelineRunId;` with doc comment "Set by RoleCaller for pipeline role calls; copied to the ledger row."
- `apps/sidecar/src/validation/**` (matching optional field, if `LlmRequest` has a validator)
- `apps/sidecar/src/services/role-caller.ts`, `llm-router.ts`, `ledger-service.ts`, `pipeline-orchestrator.ts` (+ their tests)
- `apps/sidecar/src/ports/ledger-repository.ts`, `apps/sidecar/src/infra/sqlite/ledger-repository.ts` (+ test)
- `apps/sidecar/src/container.ts` — only the attribution pass-through and the orchestrator cost dependency (another task edits this file in parallel; keep the diff minimal)
- `apps/sidecar/test/integration/pipeline.test.ts` (extend TC-M6-001 only)

## Requirements
1. `RoleCaller` sets `pipelineRunId` on every `LlmRequest` it sends (including the JSON re-ask).
2. `RouterCompleted` carries `pipelineRunId` when present; the ledger recording path stores it on the `LedgerEntry` (the column already exists). Billed failures keep the attribution too.
3. `ILedgerRepository.sumByPipelineRun(runId): Promise<MicroUsd>` (SQL aggregate through Drizzle, no raw SQL); the orchestrator takes `runCost(runId) => Promise<MicroUsd>` instead of the constant `money` and persists/publishes the run cost as `MoneyDisplay` after every role call and at the end.
4. No behaviour change for chat requests (no `pipelineRunId` → column stays null).

## Tests
- Unit: role caller attaches the id (first call and re-ask); router completed event carries it; ledger service persists it; repository sum (0 rows → 0, mixed runs, billed failure included); orchestrator cost increases after each role call.
- Integration: extend `TC-M6-001` — after COMPLETED, `pipeline.get` cost `microUsd` > 0 and equals the sum of `ledger.query` rows whose `pipelineRunId` is the run id.
