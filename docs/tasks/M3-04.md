# M3-04 — Manual pricing updater (`pricing.refresh`)

Milestone: M3 · Depends on: M3-01, M2-07 · Role: Implementer (ROLES §1.3) · **Deps pre-installed**

## Goal
When the user clicks "Update prices", fetch each provider's pricing page, let the extraction model turn it into `PriceEntry[]`, validate the result strictly, and either apply it as a new price-table version or keep the current table with a clear reason (D9, Q-05 = manual only, ARCH §6.2).

## Requirements
1. `pricing.refresh` runs one update at a time (a second call while running returns the same in-flight result). Returns `PriceUpdateRun`; publishes `pricing.updated` with the same run on every outcome.
2. Fetch every URL of `pricing.sources.json` (GET, 15 s timeout, ≤ 2 MB body); HTML → text, truncated to 200 KB. All fetches failed → `fetch_failed` (with `AppError`); some failed → continue with the rest (those providers' models count as omitted).
3. One extraction call per provider via the router: `purpose = 'pricing_extraction'`, `responseFormat = json`, model `settings.pricing.extractionModelKey`, prompt = ROLES §2.5 verbatim via `domain/template.ts`, page text inside the `<context>` block **neutralised** like other context blocks (case-insensitive `</context>`). Output zod-validated as `{entries: PriceEntry[]}`; invalid JSON → one re-ask, then that provider counts as failed.
4. Validation (`price-validation.ts`, pure): only models of that provider in the registry are accepted (unknown keys dropped and reported in a warning log); all rates are integers ≥ 0 and ≤ 1 000 000 000 µUSD/MTok; per field `percent = (new − old) / old × 100` (old = 0 and new > 0 → `percent = 100`; both 0 → 0); any `|percent| > settings.pricing.maxAutoChangePercent` → whole run `rejected_validation` with all `deltas` reported and nothing applied.
5. Apply: omitted models keep their current entry; models with an active manual override keep the override (D9: manual wins until cleared); if nothing changed → `no_change` (no new version); else new `PriceTable` version `origin = 'auto_extracted'` → `applied` with `newVersion`. Ledger rows keep their frozen cost (no recomputation).
6. Extraction calls are metered like any router call (ledger `purpose = pricing_extraction`, project = the active project or the "global" attribution the router already uses for non-project calls — follow the existing convention; if none exists, write `## Blocked`).
7. `default-settings.ts`: `pricing.autoUpdate` defaults to `false`; no scheduler is added.

## Tests
- Pure validation: BVA on Δ% (exactly limit accepted, limit + 0.01 rejected), old 0 → new 0 / new > 0, negative / non-integer / above-cap rates, unknown model dropped.
- Updater (fake HTTP, fake router): applied, no_change, rejected_validation (nothing applied), fetch_failed, partial fetch failure, invalid JSON → re-ask → success / fail, manual override preserved, prompt contains neutralised page text when the page contains `</CONTEXT>`, concurrent refresh shares one run.
- Integration `TC-M3-020`: scripted extraction reply (`ITSTUDIO_E2E_LLM_TEXT` / script fixture) with +10 % on one model → `applied`, `pricing.get` shows the new version, an older ledger row keeps its cost; `TC-M3-021`: +80 % → `rejected_validation`, table unchanged.
