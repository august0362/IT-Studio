# M1-06 — Secret store (OS keychain) + secrets RPC

Milestone: M1 · Depends on: M1-02 · Role: Implementer (ROLES §1.3) · **Deps pre-installed** (`@napi-rs/keyring`)

## Goal
Provider API keys are stored only in Windows Credential Manager, never returned to the UI, and can be verified with a cheap provider call.

## Read first
- `AGENTS.md`, `ARCHITECTURE.md` §11 (key leakage row), CONTEXT D2, `CONVENTIONS.md` §7, `schemas.ts` §3 (`SecretStatus`), §10 (`secrets.*`)

- `apps/sidecar/src/services/secrets-service.ts`, `apps/sidecar/src/infra/http/provider-key-verifier.ts`
- `apps/sidecar/src/container.ts` (register `secrets.*`), tests next to files

## Requirements
1. `ISecretStore { get(provider): Promise<Result<string | null>>; set(provider, key): Promise<Result<void>>; delete(provider): Promise<Result<void>> }`. Keychain impl: service `itstudio`, account = `ProviderId`. Memory impl for tests.
2. `SecretsService`:
   - `set(provider, apiKey)`: trim; reject empty, > 512 chars, or containing whitespace/control chars (VALIDATION); store; return `SecretStatus` with `hint` = last 4 chars only.
   - `status()`: for every `ProviderId`, `configured` + `hint` (+ `lastVerifiedAt` kept in memory).
   - `verify(provider)`: GET the provider's list-models endpoint with the key (Anthropic `GET https://api.anthropic.com/v1/models` with `x-api-key` + `anthropic-version: 2023-06-01`; OpenAI-compatible `GET {base}/models` with Bearer — bases: openai `https://api.openai.com/v1`, xai `https://api.x.ai/v1`, groq `https://api.groq.com/openai/v1`, together `https://api.together.xyz/v1`; google `GET https://generativelanguage.googleapis.com/v1beta/models` with header `x-goog-api-key`; replicate `GET https://api.replicate.com/v1/account` Bearer). 200 → verified; 401/403 → `PROVIDER_AUTH` with remediation "Re-enter the API key for <provider>"; network/5xx → `PROVIDER_SERVER` retryable. Timeout 10 s. Uses an injectable `IHttpClient` (fetch-based impl + fake).
   - `delete(provider)`.
3. The key value must never appear in: RPC results, logs (add a test capturing logger output during set/verify), error messages, `AppError.details`.
4. Register `secrets.set`, `secrets.delete`, `secrets.status`, `secrets.verify`.

## Tests
- Validation rules; hint = last 4; status for all 7 providers.
- Verify mapping for 200 / 401 / 500 / timeout per provider family (fake HTTP), correct URL + auth header per provider.
- Leak test: logger + RPC response never contain the key string.
- Keychain impl: one test guarded by `process.env.ITSTUDIO_KEYCHAIN_TEST === '1'` (skipped by default).

- [ ] No code path returns or logs a stored key
